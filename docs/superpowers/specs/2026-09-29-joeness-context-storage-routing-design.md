# JOENESS — 표준 문서와 맥락 저장·조회 설계

상태: 2026-10-06 승인 논의 반영, 개발 후보. 배포본 0.3.2와 구분.
이 문서의 이전 설계는 Git 이력에 보존된다. 임의 경로 재사용·로드맵 제외·복잡도 임계값 기반 재편 제안은 아래 표준화 계약으로 대체한다.

## 목적

프로젝트 목표·현재 작업·검증·미해결 위험을 정확히 찾아 이어받게 한다.
이를 위해 JOENESS 설정 시 프로젝트를 표준 문서 구조로 정리한다.
파일 개수나 보고 형식 준수만으로 성공을 판단하지 않는다.

## 범위

setup-only, 공개 스킬 joeness-setup 하나. 전역 Core·백그라운드·단계 실행 엔진 없음.
이번 구현은 제품 소스와 격리 시험만 변경한다. 개인 설치, 실제 프로젝트 재편,
배포·커밋·푸시는 별도 승인 범위다. Product/JOEFLOW·시각 판단/JOEDESIGN 역할을 가져오지 않는다.

## 문서 책임

| 원본 | 책임 | 제외 |
|---|---|---|
| AGENTS.md | 작업 규칙, 위치, 읽기·갱신 조건 | 이력·진행표 |
| ROADMAP.md | 프로젝트 목표, 순서, 필수 결과·검증, 현재 상태·다음 작업 | 운영 규칙·소유권 표·상세 조사/작업 |
| TASK.md | 항목별 실행 결과·검증·근거·한계 | 두 번째 현재 진행표 |
| ISSUES.md | 미해결·우회 문제의 원인·잔여 위험·종료 조건 | 모든 미완성 기능 |
| DESIGN.md | 시각 규칙·승인 원본/버전/범위·제안 | 제품 의미·진행·실행 로그 |
| Library/ | 주제별 조사·참조·재사용 지식 | 현재 진행·승인 권위 |

다섯 기준 파일을 구성하되 내용 없음/미정/해당 없음을 정직하게 표시한다.
Library는 자료 발생 시 생성한다. 같은 주제는 기존 절에 기록하고 독립 조회·재사용·갱신 필요 시 분리한다.
출처·확인일·관찰/추론·적용 범위·한계를 남긴다. 연구 주장은 승인된 제품 결정이 아니다.
기존 Product 원본은 유지한다. 별도 PRODUCT.md나 EVALUATION.md를 의무 생성하지 않는다.

## 표준화 절차

1. 현행 목표·원본·실제 상태·증거 확인. 하위 기능 계획의 존재만으로 전체 로드맵 채택 금지.
2. 이전 파일/절 → 새 담당 원본, 보존 근거, 폐기할 경쟁 상태의 변경안 제시.
3. 승인 뒤 기준 파일 구성. 적합한 내용은 유지하고 미확정 사실은 대기 표시.
4. 이전 상세·승인·실패 근거 보존. 오래된 진행 원본은 이력/범위 제한을 명시해 관리 이원화 해소.
5. 실제 결과를 다시 읽어 책임·필수 조건·근거·다음 작업 확인. 미승인 이동이나 입력 누락은 정확히 미완료 보고.

프로젝트 설정은 표준화를 포함하지만 사용자 문서 무단 삭제 권한은 아니다.
관련 자료를 따라 조사하되 전체 저장소·자산·과거 로그의 반복 정독을 의무화하지 않는다.
역할별 같은 상세를 여러 곳에서 유지하지 않는다. 로드맵 상태 요약과 TASK 실행 근거의 연결은 허용한다.

## 읽기 우선순위와 갱신 책임

작업 방식은 AGENTS, 구현 목표·순서·완료 기준은 ROADMAP, 실제 사실은 현행 대상·근거,
잔여 위험은 ISSUES, 시각 승인은 DESIGN, 참고 근거는 Library가 담당한다.
문서 고정 서열이나 숫자 가중치로 승인과 관찰을 섞지 않는다.

- 새 작업/재개: ROADMAP → 관련 TASK/ISSUES/대상. 담당자가 결과와 영향받은 상태·다음 작업 갱신.
- 결함: ISSUES/실제 대상 → TASK → ROADMAP 영향. 조사자가 원인·우회·잔여 위험·종료 조건 갱신.
- 시각: ROADMAP 범위 → DESIGN → 관련 Library. 승인 없이 디자인 기준 변경 금지.
- 조사: ROADMAP 질문 → 관련 Library. 상세는 Library, 수행 결과는 TASK, 단계 상태는 ROADMAP.
- 완료/인계: ROADMAP 필수 항목 → TASK 근거 → ISSUES → 해당 승인. 반복 기록 금지.

사용자/프로젝트 책임자가 방향·범위·수락 결정(A), 담당자가 실행·사실 기록(R).
필요한 실제 관계자만 참여(C)/공유(I). 일상 사실 기록은 동의 범위에서 재승인 불필요.
기록 금지와 읽기 전용 요청은 유지한다.

## 완료 조건

ROADMAP에는 범위, 현재 단계, 다음 작업, 단계 진입/종료 조건과 항목별 ID·상태·검증·근거/공백을 둔다.
독립 검증 조건을 분리하고 구현 세부사항까지 체크리스트로 늘리지 않는다.
검증 대기·보류는 완료가 아니다. 범위 제외는 승인·이유와 함께 보존하며 통과로 세지 않는다.
미정 목표는 결정 대기이며 허구의 계획이나 승인을 만들지 않는다.

기본 검증 방법은 로드맵 항목에, 복잡한 재사용 방법은 원본 링크로,
실행 결과는 TASK에 둔다. 공통 완료 판정 절차는 AGENTS만 소유한다.
서식은 결과 필드이며 별도 운영 매뉴얼이 아니다.

적합성은 필요한 항목뿐 아니라 중복 원본·불필요한 파일·변경 시 갱신 부담·조회 가능성까지 검사한다.
연결 정상/문서 적합/실제 지침 전달/작업 검증/사용자 수락을 따로 판정한다.

## 검증 범위

기존 패키지·설치·소유권 검사를 보존하고 정적 서식 검사를 추가한다.
격리 프로젝트에서 잘못된 하위 계획 재사용, 실제 표준화, 작은 조사 배치, 우회책,
읽기 전용 인계와 경쟁 원본의 적합성 보류를 관찰한다.
기대 답안을 실행자에게 주지 않는다. 실패와 미검증을 보존하며 정적 통과를 행동 증명으로 대신하지 않는다.
보편적 성능·토큰 절감·실제 앱 자동 주입은 별도 근거 없이는 미검증이다.

## 2026-10-07 자체 QA 보강

QA-01은 기록 동의가 민감 원문 복사 동의로 확대되는 경계의 누락,
QA-02는 병렬 작업의 통합 담당·최신 원본 대조·충돌 처리 누락이다.
실제 유출·갱신 손실은 재현되지 않았다. SKILL과 프로젝트 AGENTS 서식에만
필요한 짧은 실행 규칙을 두고 안내에는 기능의 한계를 설명한다.
TASK/ROADMAP 서식에 공통 규칙을 복제하거나 자동 비식별화·잠금 엔진을 추가하지 않는다.
QA-03 반복 설명은 기존 한계로 유지하며 기각된 축약 규칙은 재도입하지 않는다.
QA-04는 도입 적합성 안내만 추가한다. 표준 문서 필수 조건을 완화하지 않는다.

## JOENESS·JOEFLOW 연결 계약 초안 — 미합의·미배포

이 절이 공동 초안의 단일 원본이다. 제품 결정 장부나 실제 GEO의 새 규칙이 아니다.
QA의 T002~T004는 평가 근거이며, 각 제품의 승인·현황 원본을 대신하지 않는다.
사용자 제안인 ‘지속 기억은 JOENESS, 모호함 해소는 JOEFLOW’에서
기록 위치·탐색을 관리하는 책임과 제품 의미를 승인하는 권한을 구분한다.
setup-only만으로 제품 결정 권한을 가져오거나 기존 state를 폐기하지 않는다.

### 최소 호환안 — 기존 원본 유지

| 항목 | 책임과 인터페이스 제안 |
|---|---|
| 단일 결정 원본 | 프로젝트 AGENTS에 정확한 Product 원본 경로와 쓰기 담당을 지정. JOEFLOW 사용 프로젝트는 기존 `product-definition/<slug>/state.json` 유지. JOENESS는 위치·기록 책임 연결, JOEFLOW는 그 원본의 제품 정의·검토 절차 담당 |
| 식별 | 관찰 참조 = 원본 경로 + schema + stable DEC/UNK ID + definition revision + 정확한 바이트 SHA-256. 실제 승인본을 참조할 때만 승인된 semantic digest/Approval Manifest identity를 결속. OPEN/UNAPPROVED에 승인 identity를 만들어 넣지 않음. 파일 해시는 semantic 승인 digest의 대체가 아님 |
| 읽기·쓰기 | JOEFLOW 담당은 동의한 제품 정의 변경만 state에 기록. JOENESS 설정자는 연결 규칙을, 실제 작업/기록 통합 담당자는 TASK 결과와 영향받은 ROADMAP 요약을 갱신. JOENESS 설치기가 state를 수정하지 않음 |
| 승인 | 권한자 답변/채택 근거와 적용 범위를 제품 원본에 기록. 부분 결정 채택, 제품 전체 승인, 시각 승인, QA 통과, 단계 완료를 각각 유지. 자료 사용 방향 채택은 자료별 사용 허락의 증거가 아님 |
| ROADMAP 반영 | 영향받은 항목에 ‘결정된 부분 / 열린 조건 / 단계 영향’과 ID·원본 버전 참조만 기록. 결정 상세는 복제하지 않음. TASK에는 수행·검증과 미반영 위치만 기록; 별도 동기화 장부는 만들지 않음 |
| 중단·재개 | 원본 반영과 요약 갱신은 단일 트랜잭션이 아님. 원본만 반영됐으면 TASK의 기록 인계 공백에 미갱신 항목을 남기고 보고. TASK도 저장 못 하면 응답에 위치·기준 버전·미반영 범위를 명시. 재개 시 실제 원본/요약을 읽고 필요한 요약만 반영; 이미 채택된 결정을 재생성·재승인하지 않음 |
| 변경·무효화 | 파일 SHA/전체 revision 차이는 재대조 신호이지 일괄 무효화 조건이 아님. 제품 의미 변경 시 현재 Product Definition 승인은 exact revision/definition/Manifest 기준으로 stale/UNAPPROVED. 이와 별개로 이전 승인본의 downstream 2.1 계약은 소비 seed/basis/scope 불변 audit 시 OLDER_APPROVED_REVISION_UNAFFECTED로 재사용 가능. 원래 승인 버전·digest는 덮어쓰지 않음. unconsumed evidence만 바뀌면 해당 계약의 discovery baseline 갱신 후 불변 승인 유지 가능. 관련 DEC/UNK 요약과 실제 영향 소비자만 갱신·재검증; 무관한 검토의 전면 재실행 금지 |
| 단독 사용 | JOENESS만 쓰면 기존 Product 원본을 같은 방식으로 연결하되 JOEFLOW schema/ID/Manifest를 강제하지 않음. JOEFLOW만 쓰면 현행 lifecycle을 유지하고 JOENESS의 다섯 문서를 필수화하지 않음 |

실제 형식은 새 JSON 계약이 아니라 기존 문서의 참조 표기다. 예:
`Product: <path>; revision: <n>; sha256: <hash>; DEC-001 / UNK-010`.
한 번의 작업에서 여러 항목이 같은 원본을 사용하면 공통 원본 위치를 한 번 명시하고
각 항목에는 관련 ID·차이만 남긴다. 미갱신 상태를 `current`로 숨기지 않는다.

`state.objects.tasks`는 요구사항·수용 기준·구현 추적의 제품 정의 레코드,
`TASK.md`는 실제 수행·검사 결과다. 서로 진행 장부로 복제하지 않는다.
state evidence는 사실·관찰 근거이지 자동 제품 의도·승인이 아니다. 현재 의미가 소비하는
근거의 정확한 source version/hash binding은 해당 JOEFLOW 계약대로 유지한다.

### 부분 결정 예제와 검증 조건

중립 사례: DEC-001은 공개 자료의 읽기 전용 조사 방향 채택, UNK-009 해결.
UNK-010은 외부 자료 재사용 권리 미확인, 제품 전체 OPEN/UNAPPROVED.
ROADMAP은 이 세 사실을 분리한다. 다음 revision에서 방향이 바뀌면
그 방향을 소비한 이전 검토는 새 결정을 지지하는 증거가 아니다. 반대로
관련 seed/scope가 불변인 기존 승인 계약은 원본 계약의 audit 후 재사용 가능하다.
원본 갱신 후 ROADMAP 쓰기 중단을 가정하고, 재개 시 최신 DEC/UNK와
미갱신 항목만 대조해 요약을 복구한다. 권리 해결·제품 승인·단계 완료를 만들지 않는다.
이는 설명용 계약 사례다. 실제 T008 중립 사본 실행은 아래 검증 절과 구분한다.

GEO 현행 S2-1에는 이미 방향 채택/권리 미확인의 구분이 들어 있다.
QA INT-01은 옛 문구의 관찰로 유지하며 현재 미수정 결함으로 재개방하지 않는다.

### 아키텍처 변경안 — 별도 결정 필요

JOENESS가 제품 결정 원본 자체를 소유하려면 setup-only 범위를 확장하는 별도 설계가 필요하다.
새 원본의 schema/소유권, JOEFLOW state의 대체 또는 종속 관계, stable ID·승인 근거·정확한 버전의
무손실 이전, 기존 사용자·단독 사용 호환성, 중단 복구와 기존 검토 무효화를 먼저 확정해야 한다.
기존 state와 새 문서가 모두 승인 원본이 되는 중간 상태는 허용하지 않는다.
영향: JOENESS SKILL/서식/helper 범위와 JOEFLOW state schema/validator/closure/manifest/
handoff/reentry 및 해당 검사. 현재 단계에서는 구현·이전·새 필수 PRODUCT 문서 생성 없음.

남은 선택: 최소 호환안 채택 여부, 실제 프로젝트의 통합 담당, JOEFLOW가 보장하는
