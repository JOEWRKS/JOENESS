# JOENESS 침묵형 Core와 `$spec` 설계

**작성일:** 2026-08-11  
**상태:** 대화에서 승인된 설계를 구현 명세로 고정  
**대상:** JOENESS 0.1 Beta 호환 업데이트

## 결과

JOENESS는 정상 작업의 절차나 응답 형식을 소유하지 않는다. 전역 Core는 PID 소유권, 재시도 상한, 불명확한 외부 쓰기 복구, 임시 상태 복원, 완료 증거의 정확성만 지키는 침묵형 안전 바닥으로 축소한다. 영구 명세를 새로 만들거나 내용상 크게 바꾼 뒤에는 `$spec`이 최신 파일을 다시 확인하고 사용자 언어로 짧은 결정 요약을 전달한다.

## 소유권

| 영역 | 소유자 |
|---|---|
| 범위, 티켓 생명주기, 승인, 로그, 필수 도구와 검증, 최종 보고 양식 | 현재 사용자와 프로젝트 규칙 |
| PID 종료 증명, 반복 실패 상한, 불명확한 공유·외부 쓰기, 임시 상태 복원, 허위 완료 방지 | JOENESS Core |
| 영구 명세의 작성 내용과 위치 | 해당 명세 작성 workflow 또는 프로젝트 |
| 작성·실질 변경된 명세의 사용자 언어 결정 요약 | `$spec` |

프로젝트 보고 양식이 있으면 JOENESS 사실과 명세 요약을 그 양식 안에 넣는다. 별도 5줄 영수증이나 `$spec` 블록을 덧붙이지 않는다.

## Core v4

- 정상 성공에는 JOENESS 전용 블록, 원인·처리·위험 필드, 고정 메뉴, 강제 다음 단계를 출력하지 않는다.
- 결과를 바꾸거나 진행을 막는 현재의 중요한 미결정만 사용자 언어로 묻는다. 선택지는 최대 세 개이며 추천 기본값과 대기 범위를 함께 밝힌다.
- crash나 사용자 중지 뒤에는 소유가 증명된 프로세스만 격리하고, 의도적인 임시 상태를 복원·재확인한 뒤 재실행 없이 멈춘다.
- 로컬 프로젝트 의존성 설치는 이름만으로 공유·외부 쓰기가 되지 않는다. 실제 대상 효과로 분류한다.
- 의미 있는 실패나 workaround만 프로젝트 보고에 흡수한다. 고정 줄 수가 없고 원인을 추측해 채우지 않는다.
- Core 후보는 2 KiB를 넘지 않는다. v3와 이전 후보는 역사 증거로 보존한다.

## `$spec`

### 활성화

현재 작업이 제품·설계·아키텍처·구현·프로젝트의 영구 명세 파일을 새로 만들거나, 범위·결정·요구사항·인터페이스·제약·수용 기준을 실질적으로 바꾼 직후에만 활성화한다.

읽기 전용 검토, 채팅 안의 아이디어 논의, 명세를 바꾸지 않는 구현, 오탈자·서식·링크만 고치는 작업에는 활성화하지 않는다.

### 전달 형식

프로젝트 또는 사용자가 정한 보고 형식이 있으면 기존 결과·변경·검토 필드 안에 요약한다. 없으면 현재 사용자 언어로 다음만 전달한다.

1. 명세가 무엇을 정의하는지와 정확한 최신 파일 링크를 담은 결과 한 문장
2. 선택한 방향, 실질 변경, 구현에 영향을 주는 제약 중 최대 세 줄
3. 해당할 때만 미결정·미검증·부분 완료·구현 미시작 경계 한 문장

명세 파일이 유일한 권위다. 요약은 요구사항·수용 기준·권한을 추가하거나 바꾸지 않는다. 새 승인, PM, 계획, 구현, commit, 전환 절차도 만들지 않는다.

## 설치와 평가

- 활성 공개 역할은 `$project`, `$design`, `$visual-check`, `$spec`, `$handoff` 다섯 개다.
- 설치기는 manifest를 읽으므로 새 스킬 descriptor와 파일 해시만 추가하고 설치 코드 자체는 바꾸지 않는다.
- 기존 visual v3/v4/v5, Core v1-v3, compatibility vendor 자료는 수정하지 않는다.
- 기존 visual v5 평가는 history로 이동하고, 합성 응답 검증을 포함한 v6 계약은 `candidate/unvalidated`로 시작한다.
- `$spec` 명시 적용의 응답 형식 표본은 대조군 5회와 후보 5회를 원문과 함께 보존한다. 이는 암묵 호출이나 실제 파일 readback을 증명하지 않는다.

## 합격 기준

- 정상 성공 응답에 JOENESS 전용 ceremony가 추가되지 않는다.
- `$spec`의 양성·음성 라우팅 사례와 사용자 언어 digest 계약이 집중 테스트를 통과한다.
- Core·skill·평가 artifact의 정확한 bytes와 SHA-256이 manifest 및 무결성 테스트와 일치한다.
- 설치 `Check → Apply → Check → Remove`와 전체 회귀가 기존 롤백·호환 계약을 유지한다.
