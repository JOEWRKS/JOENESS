# JOENESS 조건부 프로젝트 계획 계약

## 목적

사용자가 여러 단계가 필요한 앱·게임·웹·디자인 프로젝트를 시작하거나 크게 확장하면서 구체적인 작업계획을 제공하지 않았을 때, JOENESS가 곧바로 구현하거나 즉흥적으로 다음 단계를 반복 계산하지 않도록 한다. 기존 계획 수단이 없으면 한 번만 `TASKS.md` 생성을 제안하고, 사용자가 동의한 뒤 전체 이정표와 현재 단계의 실행 계획을 기록한다.

이 기능은 처음부터 모든 구현을 고정하는 상세 A-Z 명세가 아니다. 제품 전체는 개략적인 이정표로 유지하고, 현재 단계만 실행 가능한 수준으로 구체화하는 점진적 계획 계약이다.

## 현재 문제

- Interaction Safety Core는 질문·재시도·실패 보고를 통제하지만 프로젝트 전체 진행 상태를 보존하지 않는다.
- `joewrks-project-setup`은 `AGENTS.md`에 지속 규칙을 기록하되 변동하는 진행 상황은 기록하지 않도록 설계되어 있다.
- 프로젝트에 별도 계획 문서나 이슈 트래커가 없으면 에이전트가 대화 맥락에 의존해 다음 단계를 다시 계산할 수 있다.
- 반대로 모든 프로젝트에 초상세 계획 문서를 강제하면 작은 작업까지 지연시키고 오래된 계획과 토큰 낭비를 만든다.

실무에서도 제품 목표와 로드맵은 장기 방향을 제공하지만 작업 백로그는 진행에 따라 구체화된다. Scrum Guide는 Product Backlog를 계속 발전하는 목록으로 설명하고, GitHub Projects는 로드맵·백로그·반복 주기·이슈 계층을 함께 제공한다.

- <https://scrumguides.org/scrum-guide.html?from=hub>
- <https://docs.github.com/en/issues/planning-and-tracking-with-projects>

## 설계 결정

### 1. 기존 구성요소를 재사용한다

새 스킬·데몬·로그 시스템을 만들지 않는다.

- 얇은 Interaction Safety Core는 계획 제안 여부만 판단하고 현재 차단 질문으로 표시한다.
- 사용자가 동의하면 기존 explicit-only `joewrks-project-setup`을 호출해 프로젝트 루트를 검증하고 계획 파일을 생성하거나 갱신한다.
- `AGENTS.md`는 지속 규칙, `TASKS.md`는 변동하는 계획, Handoff는 임시 인수인계 역할을 유지한다.

### 2. 질문 조건을 제한한다

다음 조건을 모두 만족할 때만 한 번 질문한다.

1. 요청이 앱·게임·웹·디자인 시스템처럼 여러 의미 있는 단계 또는 여러 작업 세션이 필요한 프로젝트의 시작이나 중대한 범위 확장이다.
2. 사용자가 단계별 실행 계획을 제공하지 않았다.
3. 저장소에서 `TASKS.md`, `ROADMAP.md`, 이슈·프로젝트 링크, 승인된 구현 계획 등 현재 사용할 수 있는 계획 원장을 확인하지 못했다.

다음 경우에는 질문하지 않는다.

- 단일 버그 수정, 작은 편집, 조사, 설명, 브레인스토밍만 요청한 경우
- 이미 계획 원장이 있고 현재 작업을 식별할 수 있는 경우
- 사용자가 계획 문서를 만들지 말라고 했거나 이전 제안을 거절한 경우
- 같은 범위에서 이미 답한 선택을 다시 묻는 경우

### 3. 질문은 짧고 분리한다

질문은 Interaction Safety Core의 기존 확인 블록 형식을 따른다.

- 결정: 기존 계획 수단을 사용하거나 `TASKS.md`를 만들지
- 권장 기본값: 여러 단계 프로젝트라면 생성
- 대기 작업: 사용자가 답하기 전에는 영구 계획 파일 작성과 광범위한 구현을 시작하지 않음

사용자가 거절하면 영구 파일을 만들지 않고 응답 안의 짧은 현재 단계 계획으로 작업을 계속한다. 프로젝트 범위나 출시 목표가 크게 바뀌기 전에는 다시 묻지 않는다.

### 4. 기존 원장을 우선한다

계획 수단의 우선순위는 다음과 같다.

1. 사용자가 지정한 이슈 트래커·프로젝트 보드·계획 문서
2. 저장소가 현재 프로젝트에 사용 중인 `TASKS.md`, `ROADMAP.md`, `TODO.md`, 관련 `docs/plans/` 등의 관례
3. 아무것도 없을 때만 저장소 루트의 `TASKS.md`

같은 내용을 여러 문서에 복제하지 않는다. 외부 트래커가 있으면 `TASKS.md`를 새로 만들지 않고 권위 있는 링크와 현재 항목을 사용한다.

아직 검증 가능한 프로젝트 경로나 Git 저장소가 없다면 파일을 임의 위치에 만들지 않는다. 대화 안에서 개략 계획만 제시하고, 사용자가 프로젝트 위치를 정하거나 저장소를 만든 뒤 영구 계획 생성을 다시 진행한다.

## `TASKS.md` 최소 계약

새 파일은 다음 정보만 포함한다.

1. 프로젝트 목표와 출시 완료 조건
2. 전체 단계별 이정표와 상태
3. 현재 단계의 구체적인 작업 체크리스트
4. 바로 다음 우선 작업 1~3개
5. 차단 사항과 사용자 결정
6. 완료 항목의 검증 증거: 커밋, 테스트, 빌드 또는 실제 산출물
7. 마지막으로 현재 상태를 확인한 날짜와 기준 Git HEAD

전체 미래 단계는 한두 문장짜리 이정표로 유지한다. 파일·함수 단위의 상세 절차는 현재 단계 또는 복잡한 기능의 `docs/plans/...`에만 둔다.

## 갱신 규칙

- 주요 이정표 완료, 범위 변경, 새 차단 사항, 출시 기준 변경 때 갱신한다.
- 사소한 파일 수정이나 모든 도구 실행마다 갱신하지 않는다.
- `완료`는 실제 Git·파일·테스트·빌드·외부 결과로 확인한 경우에만 표시한다.
- 실패하거나 부분 완료된 작업을 완료로 바꾸지 않는다.
- 오래된 예정 작업은 현재 사실에 맞게 수정할 수 있지만, 이미 완료했다고 기록한 증거와 중요한 결정은 근거 없이 다시 쓰지 않는다.
- 계획 문서는 작업 권한을 확장하지 않는다. 외부 게시·배포·결제·공유는 현재 사용자 요청의 권한을 별도로 따라야 한다.

## 파일별 책임

| 위치 | 책임 |
|---|---|
| `AGENTS.md` | 프로젝트의 지속 목표·제약·권위 있는 문서와 실행 규칙 |
| `TASKS.md` 또는 기존 트래커 | 전체 이정표·현재 단계·다음 작업·상태·증거 |
| `docs/plans/...` | 현재의 복잡한 기능 하나에 대한 상세 구현 절차 |
| `README.md` | 사람을 위한 설치·실행·사용 안내 |
| Handoff | 다른 작업으로 넘길 때의 검증된 임시 상태 |

## 구현 범위

- Interaction Safety Core에 조건부 계획 제안 규칙을 한 문장 수준으로 추가한다.
- `joewrks-project-setup`에 기존 계획 원장 탐색, 동의 후 `TASKS.md` 생성·갱신, 최소 계약과 갱신 규칙을 추가한다.
- 설치 manifest의 변경된 Core·스킬 바이트와 SHA-256을 갱신한다.
- README 한국어·영어에 조건과 사용자 흐름을 짧게 설명한다.
- 기존 프로젝트 설정 helper는 `AGENTS.md` 관리 블록 용도로 유지한다. `TASKS.md`는 검증된 프로젝트 루트 안에서 일반 문서 편집으로 처리하며 별도 쓰기 프레임워크를 만들지 않는다.

## 검증 시나리오

1. 계획이 없는 신규 앱 요청: 한 번만 `TASKS.md` 생성을 제안하고 권장값·대기 작업을 표시한다.
2. 기존 `TASKS.md` 또는 이슈 트래커가 있는 프로젝트: 새 문서를 제안하지 않고 기존 원장을 사용한다.
3. 단일 버그 수정: 계획 문서 질문 없이 바로 범위 안에서 진행한다.
4. 사용자가 생성을 거절: 채팅의 짧은 계획으로 진행하고 같은 범위에서 다시 묻지 않는다.
5. 사용자가 동의: 전체 이정표는 개략적이고 현재 단계만 구체적인 `TASKS.md`를 만든다.
6. 완료 증거가 없는 항목: `완료`로 표시하지 않는다.
7. 범위가 크게 변경됨: 기존 원장을 갱신 대상으로 제안할 수 있으나 중복 원장을 만들지 않는다.

## 합격 기준

- 계획이 없는 다단계 프로젝트에서만 제안이 발생한다.
- 기존 계획과 사용자의 거절을 존중하고 반복 질문하지 않는다.
- `TASKS.md`가 AGENTS·README·Handoff의 역할을 복제하지 않는다.
- 계획 때문에 구현을 A-Z 세부 수준으로 선행하지 않는다.
- 완료 상태와 검증 증거가 일치한다.
- 새 스킬·서비스·의존성 없이 기존 Core와 `joewrks-project-setup`만 최소 수정한다.
- 기존 설치 계약과 디자인·Handoff 동작이 회귀하지 않는다.

## 의도적으로 하지 않는 것

- 모든 프로젝트에 `TASKS.md` 강제 생성
- 모든 미래 구현의 파일·함수 단위 사전 계획
- 별도 프로젝트 관리 앱 또는 자동 동기화
- 이슈 트래커와 저장소 문서의 양방향 복제
- 매 응답·매 명령 후 상태 문서 갱신
- 계획 문서만으로 완료나 출시 준비를 판정
