# JOENESS 조건부 프로젝트 계획 계약

## 목적

사용자가 장기간 이어질 앱·게임·웹·디자인 프로젝트를 시작하거나 출시 범위를 크게 확장하면서 구체적인 작업계획을 제공하지 않았을 때, JOENESS가 기존 계획 원장을 찾고 필요하면 영구 계획 저장을 한 번 제안한다.

이 기능은 계획 파일을 모든 작업의 승인 게이트로 만들지 않는다. 에이전트는 읽기·현황 파악과 짧은 채팅 계획을 계속하며, 사용자가 동의한 경우에만 전체 이정표와 현재 단계의 실행 계획을 프로젝트에 저장한다.

## 현재 문제와 경계

- Interaction Safety Core는 질문·재시도·실패 보고를 통제하지만 프로젝트 진행 원장을 만들지 않는다.
- `joewrks-project-setup`은 `AGENTS.md`에 지속 규칙을 기록하되 변동하는 진행 상태는 별도 원장을 가리키도록 설계되어 있다.
- 계획 원장이 없으면 새 작업의 에이전트가 대화 맥락에 의존해 다음 단계를 다시 계산할 수 있다.
- 모든 작업에 계획 문서를 강제하면 작은 작업을 지연시키고 상시 컨텍스트와 오래된 문서를 늘린다.

기존 광범위 상시 Core는 실험에서 기각됐다. 따라서 Interaction Safety Core는 변경하지 않는다. 이 기능은 기존 `joewrks-project-setup`이 관련 프로젝트 시작 요청에서만 조건부로 제안되고, 모든 쓰기는 명시적 동의 후 실행하는 방식으로 구현한다.

실무에서도 장기 방향은 로드맵으로 유지하지만 작업 백로그는 진행에 따라 구체화한다.

- <https://docs.github.com/en/issues/planning-and-tracking-with-projects>
- <https://github.github.com/spec-kit/concepts/spec-of-specs.html>

## 설계 결정

### 1. 기존 스킬을 조건부 제안에 재사용한다

새 스킬·데몬·로그 시스템을 만들지 않는다.

- `joewrks-project-setup`은 장기 프로젝트 시작·중대한 출시 범위 확장에서만 자동으로 선택될 수 있다.
- 자동 선택 단계는 읽기 전용 확인과 계획 저장 제안까지만 허용한다.
- `TASKS.md` 생성과 `AGENTS.md` 연결은 사용자가 두 변경을 명시적으로 승인한 뒤에만 수행한다.
- 이후 일상적인 상태 갱신은 해당 프로젝트의 `AGENTS.md`가 가리키는 기존 원장에서 처리한다. 설정 스킬을 매 작업마다 다시 실행하지 않는다.
- Interaction Safety Core와 Handoff는 변경하지 않는다.

### 2. 제안 조건을 제한한다

다음 조건을 모두 만족할 때만 현재 작업에서 한 번 제안한다.

1. 요청이 프로젝트 수준이며 여러 세션·마일스톤·협업자 또는 실제 출시 과정으로 이어질 가능성이 높다.
2. 사용자가 단계별 실행 계획을 제공하지 않았다.
3. 고정된 짧은 후보 목록과 프로젝트 규칙에서 현재 사용할 수 있는 계획 원장을 찾지 못했다.

확인 후보는 사용자가 지정한 트래커와 프로젝트 규칙이 가리키는 문서, 저장소 루트의 `TASKS.md`, `ROADMAP.md`, `TODO.md`, 그리고 현재 기능과 직접 연결된 승인 계획으로 제한한다. 선택되지 않은 계획 문서 전체나 외부 트래커를 광범위하게 읽지 않는다.

다음 경우에는 제안하지 않는다.

- 단일 버그 수정, 작은 편집, 조사, 설명 또는 브레인스토밍만 요청한 경우
- 기존 계획 원장이 있고 현재 작업을 식별할 수 있는 경우
- 사용자가 현재 작업에서 영구 계획 저장을 거절한 경우
- 검증 가능한 프로젝트 경로나 Git 저장소가 아직 없는 경우

거절은 현재 작업에만 적용한다. 새 작업에서도 거절을 기억한다고 주장하거나 별도 거절 상태를 만들지 않는다.

### 3. 계획 작성 여부만 기다린다

제안 전후에도 에이전트는 안전한 읽기·현황 파악과 짧은 현재 단계 계획을 진행할 수 있다. 기다리는 것은 영구 계획 파일 작성과 계획에 근거한 광범위 구현이다.

질문은 사용자 언어로 다음 내용을 한 번에 밝힌다.

- 왜 장기 계획 원장이 유용한지
- 새로 만들 파일과 변경 범위: `TASKS.md`, `AGENTS.md`의 계획 위치 한 줄
- 권장 기본값과 사용자의 답변 전 기다리는 작업

사용자가 거절하면 파일을 만들지 않고 채팅의 짧은 계획으로 요청 범위 안의 작업을 계속한다.

### 4. 기존 단일 원장을 우선한다

계획 수단의 우선순위는 다음과 같다.

1. 사용자가 지정한 이슈 트래커·프로젝트 보드·계획 문서
2. 프로젝트 `AGENTS.md` 또는 README가 권위 있다고 지정한 원장
3. 저장소가 현재 사용 중인 계획 관례
4. 아무것도 없을 때만 저장소 루트의 `TASKS.md`

외부 트래커가 있으면 `TASKS.md`를 새로 만들거나 내용을 복제하지 않는다. 프로젝트 `AGENTS.md`에는 선택된 원장 위치와 최소 갱신 규칙만 기록하고 현재 작업 목록을 복사하지 않는다.

## `TASKS.md` 최소 계약

`TASKS.md`는 가급적 4 KiB 이하로 유지하며 다음 정보만 포함한다.

1. 제품 목표·출시 조건의 권위 있는 문서 링크 또는 한 줄 요약
2. 얕은 전체 이정표와 현재 상태
3. 현재 마일스톤과 바로 다음 우선 작업 1~3개
4. 각 현재 작업의 결과·수용 조건·상태, 협업 시에만 담당자
5. 현재 차단 사항·사용자 결정·권위 있는 링크
6. 완료 항목의 간결한 증거 참조: 커밋, 명령과 결과, 빌드 또는 산출물 경로
7. 마지막 검토 날짜와 검토한 근거 종류

사용자나 기존 제품 문서가 정하지 않은 이정표·출시 조건은 `provisional` 계획 가정으로 표시한다. 이는 새 요구사항·완료 기준·외부 행동 권한이 아니다.

전체 미래 단계는 이름·의도·범위 경계 수준으로 유지한다. 파일·함수 단위 절차는 현재 마일스톤 또는 복잡한 기능의 `docs/plans/...`에만 둔다. 원시 로그·Handoff 본문·긴 테스트 출력을 복사하지 않는다.

`TASKS.md`는 현재 상태를 찾는 원장이지 사실 증명 자체가 아니다. 작업을 시작하거나 완료를 주장하기 전에 현재 Git·파일·테스트·빌드·실제 외부 상태와 조정한다. 전체 HEAD를 최신성 필드로 기록하지 않으며, 완료 항목에 필요한 근거 커밋만 참조한다.

## 갱신 규칙

- 마일스톤 시작·완료, 범위·출시 조건 변경, 결정·차단 변경, 계획된 인수인계 전에 원장이 낡았을 때만 갱신한다.
- 사소한 파일 수정, 모든 명령, 모든 응답 또는 모든 커밋마다 갱신하지 않는다.
- `완료`는 현재 증거가 확인된 경우에만 표시한다.
- 실패·부분 완료·미검증을 완료로 바꾸지 않는다.
- 예정 작업은 현재 사실에 맞게 조정할 수 있지만 완료 증거와 중요한 결정을 근거 없이 다시 쓰지 않는다.
- 계획 원장은 작업 권한을 확장하지 않는다. 외부 게시·배포·결제·공유는 현재 사용자 요청의 권한을 별도로 따른다.

## 파일별 책임

| 위치 | 책임 |
|---|---|
| `AGENTS.md` | 지속 목표·제약·권위 있는 문서와 계획 원장 위치 |
| `TASKS.md` 또는 기존 트래커 | 얕은 이정표·현재 단계·다음 작업·상태·증거 참조 |
| `docs/plans/...` | 현재의 복잡한 기능 하나에 대한 상세 구현 절차 |
| `README.md` | 사람을 위한 설치·실행·사용 안내 |
| Handoff | 다른 작업으로 넘길 때의 검증된 임시 상태 |

## 구현 범위

- Interaction Safety Core는 변경하지 않는다.
- `joewrks-project-setup`을 조건부 제안·명시적 쓰기 모델로 조정한다.
- 동의 후 일반 문서 편집으로 `TASKS.md`를 만들고, 기존 snapshot helper로 `AGENTS.md` 관리 블록에 원장 위치와 최소 갱신 규칙을 연결한다.
- skill metadata와 manifest의 활성 정책·바이트·SHA-256을 갱신한다.
- README 한국어·영어에 조건, 동의 범위, 거절 시 동작을 짧게 설명한다.
- 새 쓰기 프레임워크·서비스·의존성을 추가하지 않는다.

## 최소 검증

1. 장기 프로젝트·계획 없음: 한 번 제안하며 쓰기는 동의 전 실행하지 않는다.
2. 기존 원장 있음: 새 문서나 중복 원장을 제안하지 않는다.
3. 단일 버그 수정: 계획 저장을 제안하지 않고 요청을 진행한다.
4. 현재 작업에서 거절: 파일을 만들지 않고 같은 작업에서 다시 묻지 않는다.
5. 동의: `TASKS.md`를 만들고 `AGENTS.md`에는 위치와 갱신 규칙만 연결한다.
6. 완료 증거 없음: 완료로 표시하지 않고 provisional·partial·unverified를 유지한다.

광범위 A/B나 새 평가 프레임워크는 만들지 않는다. 기존 계약 테스트와 위 여섯 시나리오의 최소 행동 표본만 사용한다. 조건부 스킬 선택이 반복적으로 실패한다는 실제 증거가 생길 때만 짧은 Core 보강을 별도 검토한다.

## 합격 기준

- 단순 작업과 기존 트래커 프로젝트에 추가 질문·파일·컨텍스트 비용이 없다.
- 자동 선택은 읽기·제안만 수행하고 모든 쓰기는 설명된 대상에 대한 명시적 동의 뒤에 실행한다.
- 기존 계획 원장을 단일 사실 위치로 유지한다.
- 미래 계획을 과도하게 상세화하지 않고 현재 단계만 실행 가능하게 만든다.
- 상태 문서와 현재 증거가 충돌하면 현재 증거를 우선한다.
- 새 스킬·서비스·의존성 없이 기존 `joewrks-project-setup`만 최소 수정한다.
- 기존 설치·디자인·Handoff·Interaction Safety Core 동작이 회귀하지 않는다.

## 의도적으로 하지 않는 것

- Interaction Safety Core 확장
- 모든 프로젝트에 계획 파일 강제 생성
- 영구 계획 저장 여부를 모든 작업의 승인 게이트로 사용
- 모든 미래 구현의 파일·함수 단위 사전 계획
- 별도 프로젝트 관리 앱·자동 동기화·거절 기억 저장소
- 이슈 트래커와 저장소 문서의 양방향 복제
- 매 응답·명령·커밋 후 상태 문서 갱신
- 계획 문서만으로 완료나 출시 준비 판정
