# JOENESS 표준 문서 운영 구현 계획

상태: 2026-10-06 로컬 후보 구현·한정 검증 완료. [설계](../specs/2026-09-29-joeness-context-storage-routing-design.md).
기존 계획의 Core·임의 경로 우선·복잡도 임계값은 현 승인 설계로 대체.
개인 설치·실제 프로젝트·배포는 변경하지 않는다.

## 1단계 — 기준과 실패 검사

- [x] 현행 규칙·서식·사용 안내·검사 대조.
- [x] 변경 전 Node 9/9 및 로컬 출시 계약 통과.
- [x] 로드맵 검증 행·기록별 책임 서식 검사 추가, 수정 전 0/2 확인.
- [x] 설계·계획에 표준화, 단일 원본, 작업별 우선순위 명시.

완료 조건: 기존 경계와 변경 요건 식별, RED 결과 보존.

## 2단계 — 소스와 안내

- [x] SKILL: 표준 다섯 파일, 필수 ROADMAP, 승인된 기존 자료 재규격화.
- [x] AGENTS: 작업별 읽기/기록/완료 판단. ROADMAP: 결과 데이터만.
- [x] TASK 실행, ISSUES 잔여 위험, DESIGN 시각 승인, Library 주제 저장 구분.
- [x] 사용 안내·README·manifest 후보 일치 확인.

완료 조건: 규칙→서식→사용 안내 충돌 해소. helper의 소유권/재시도 안전 경계 유지.

## 3단계 — 격리 행동 검증

- [x] 관련 없는 기존 계획이 있는 프로젝트의 연결 제안.
- [x] 승인된 재규격화로 완료·미완·우회·시각 승인 경계 보존.
- [x] 작은 조사 저장/갱신에서 기존 주제 원본 유지, 새 파일 없음.
- [x] 새 담당자 읽기 전용 인계에서 목표·현재·다음·근거 복원. 자동 주입은 미검증.
- [x] 연결 정상이어도 경쟁 원본을 찾아 문서 적합 판정 거부.

완료 조건: 실제 산출물·변경 경계·응답 대조. 실패는 수정 후 해당 사례만 재검증.
평가자에게 기존 기대 답·의심 결함을 주입하지 않는다. 실프로젝트에는 적용하지 않는다.

## 4단계 — 회귀와 인계

- [x] Node 전체 12/12, PowerShell 5/7 연결 각 27/27·설치, 출시 계약, 스킬 형식 검사.
- [x] 변경 파일 해시·검증 한계·개인 설치 9파일 불변 기록.
- [x] 다음 작업과 알려진 실패를 제품 ROADMAP에 반영.

완료 조건: 후보 구현 검토 가능 상태. 정식 출시 완료가 아니다.
정확한 출시 커밋의 Windows CI·개인 설치 확인·배포 승인은 후속 단계.

[검증 근거](../../../evals/joeness-setup/runs/2026-10-06-document-normalization/review-evidence.md): 독립 실행은 런타임 ID가 노출되지 않아 특정 모델 통과로 주장하지 않는다. 보고가 긴 경향, 앱 자동 전달·실제 프로젝트 일반화는 별도 한계로 유지한다.
