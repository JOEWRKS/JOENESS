### C3 — 프로젝트 helper 계약

논리 함수: `Invoke-JoenessProjectSetup`의 parameter sets는 `Check`, `Apply`, `Detach`다. CLI는 설계 문서 C3의 옵션과 동일하다. `-ExpectedTargetHash`와 `-ExpectedStateHash`는 `absent` 또는 소문자 SHA-256이며 쓰기 동작에 필수다.

결과 JSON 필드: `action`, `status`, `projectRoot`, `target`, `targetHash`, `statePath`, `stateHash`, `blockState`, `changedTargets`, `blockers`, `rollback`, `unresolvedTargets`. `status`는 `ready|current|detached|blocked|failed|partial`, `blockState`는 `absent|clean|edited|unowned|malformed|legacy`다. Check는 관찰 상태를 반환할 뿐 제안 본문 없이 내용의 no-op 여부를 주장하지 않는다.

새 marker는 `<!-- JOENESS-SETUP:BEGIN -->` / `<!-- JOENESS-SETUP:END -->`. 기존 `JOEWRKS-PROJECT`는 legacy로 식별한다. 새 상태 파일의 schema 1 필드는 `schemaVersion`, `toolVersion`, `targetRelativePath`, `appliedBlockBase64`, `appliedBlockSha256`, `ownedBoundary`다. `ownedBoundary`는 삽입한 구역 앞/뒤 separator bytes만 표현한다. AGENTS의 나머지 본문은 저장하지 않는다. 상태가 존재하면 내부 hash·고정 상대 경로·marker·UTF-8을 먼저 검증한다. 이 자료는 보안상 신뢰나 사용자 승인을 대신하지 않는다.

지원 bytes는 엄격한 UTF-8(선택적 BOM), LF/CRLF, 끝 개행 유무다. 본문 밖 bytes를 그대로 splice하며 unsupported encoding은 무변경 차단한다. 자동 update/Detach는 현재 구역 bytes가 적용 기준과 같을 때만 허용한다. boundary bytes도 일치할 때만 함께 제거하고, 바뀐 구역 밖 내용은 보존한다. Detach는 빈 AGENTS 파일도 남긴다.

Git root가 확인되는 프로젝트를 첫 자동 적용 대상에 포함한다. non-Git 최초 자동 적용은 미확정 지원 범위이므로 현재 계획에서는 무변경 `blocked`로 명시하고 지원한다고 배포하지 않는다. non-Git 읽기·설명·기록 전달은 C2에서 검증하며 임의 `git init`은 하지 않는다.

## Task 2 — AGENTS 적용 기준과 Check/Apply/Detach

**Files:** create helper and `tests/joeness-project-setup.tests.ps1`.

**Interfaces:** 위 C3 CLI/JSON/schema. 입력은 확인된 현재 두 파일과 제안 본문, 출력은 실제로 바뀐 대상/실패 경계다. 문서 의미 판단 API는 만들지 않는다.

- [ ] `InitialApplyAndNoOp` RED: 첫 적용은 AGENTS와 적용 기준을 만들고 동일 재실행은 bytes와 쓰기 이벤트가 변하지 않는다.
- [ ] `InsideEditSurvivesFreshCheck` RED: 내부 사용자 문장 추가 후 새 Check를 하더라도 Apply/Detach는 edited 충돌로 끝나며 두 파일을 보존한다. 변경안을 새로 승인받지 않고 상태를 덮어써 소유권을 인수하지 않는다.
- [ ] `OutsideBytesAndDetach` RED: BOM/LF/CRLF/끝 개행 변형과 외부 편집을 보존하며 clean Detach는 운영 구역만 제거한다. 두 번째 Detach는 무변경이다.
- [ ] `MalformedOrUnownedOrLegacy` RED: marker 손상/중복, 상태 파일 불일치·타 도구 경로 충돌, 0.1 구역에서는 자동 변경을 차단한다.
- [ ] `StateWriteFailureAfterUserEdit` RED: 첫 파일 쓰기 뒤 실패를 주입한다. 직전 도구 bytes와 같으면 복구하고, 사용자가 다시 바꿨으면 그 편집을 보존하며 partial/unresolved를 반환한다.
- [ ] `SnapshotAndRootDrift` RED: Check 이후 target/state/root/reparse 변경을 차단한다. clone된 정상 Git 프로젝트는 현재 명시 root로 state 상대 경로를 다시 결합하며 예전 절대 root를 요구하지 않는다.
- [ ] 최소 구현 후 `powershell.exe -NoProfile -ExecutionPolicy Bypass -File tests/joeness-project-setup.tests.ps1` 실행: 모든 위 의미 사례 통과·실패 0. no-op 검증은 내용 hash뿐 아니라 write 경로 호출 여부도 확인한다.

- [ ] setup 의도가 분명한 요청에 implicit 선택을 허용하는 설명과 명시 호출 대안을 작성한다. 일상 수정 요청은 setup 재호출 조건에서 제외한다.

**Interfaces:** 실제 런타임은 설치/연결된 지침과 사용자 요청만 받는다. evidence는 `caseId`, exact runtime identity, prompt/skill/fixture revision, 전후 파일 diff, 관련 read/write/action 근거, 결과와 한계를 갖는다. 기대 답안은 평가 쪽에만 둔다.

- [ ] C2-A~C에서 실제 Git 기록 복원·최신 미보존 내용 유지·활성 이슈 이월·이력 부재 보고를 확인한다. 별도 아카이브 엔진은 만들지 않는다.
- [ ] clean Detach 또는 자동 기록 중지 후 새 컨텍스트에서 해당 운영 지시가 더 이상 적용되지 않는지 확인한다. 상위 지침이 같은 기록을 요구하면 그 출처를 구분한다. edited 구역은 충돌과 보존 결과를 확인한다.

- [ ] 각 명확한 실패를 보존하고 원인을 수정한 경우에만 영향 case를 재실행한다. 다른 모델/앱/표현으로 일반화하지 않고 실제 identity와 범위를 기록한다. 현재 세션에 fresh 실행 수단이 없으면 미실행으로 남긴다.

**Files:** README, 앞 task tests/evidence. 새 사용자용 필수 프로젝트 파일은 추가하지 않는다.

**Interfaces:** README의 실제 명령은 Tasks 2/4에서 검증한 인터페이스만 사용한다. 프로젝트 helper의 내부 옵션은 일반 사용자의 필수 조작법으로 노출하지 않고 자연어 사용을 우선한다.

- [ ] 문서의 설치 예는 임시 home에서 실행하고, 일반 요청 예는 Task 5 결과와 대조한다. 앱 지침 재로딩을 실제 확인하지 못하면 CLI 결과로 대신 보증하지 않는다.
- [ ] 처음 쓰는 사람의 안내 이해 확인은 별도 기록한다. 시행하지 않았다면 `not-run`; 자동 점검 통과를 `user-accepted`로 바꾸지 않는다. 별도로 요구되지 않은 사용자 조사를 새 코딩 중단 절차로 강제하지 않는다.
