# JOENESS 0.3 정식 출시 로드맵

기준: 2026-09-28. 이 문서는 **JOENESS 제품의 출시 준비**를 다룬다. `skills/joeness-setup/assets/ROADMAP.md`는 사용자의 *각 프로젝트*에 쓰는 참고 서식이며 이 문서와 다르다.

2026-09-28 베타 상태: `0.3.0-beta.1` 태그의 커밋 `6e8963c`가 `main`에 반영됐고 개인 설치 `-Check`는 `current`였다. 이는 **정식 출시 완료나 일반 사용자 검증 완료가 아니다.** 아래 미완 항목과 최종 사용자 승인은 그대로 남는다.

현재 `0.3.0-beta.2-dev` 소스 후보에는 이후의 맥락 저장·조회 변경도 포함된다. 앞선 단계별 로드맵 연결 후보를 2026-09-29 개인 설치에 갱신한 기록은 있지만, **현재 소스**의 개인 설치 `-Check`는 manifest 불일치로 `blocked`이다. 현재 후보를 설치·출시 승인하거나 원격 배포하지 않았다. 기존 `0.3.0-beta.1` 평가 결과는 그대로 보존한다.

## 목표와 완료 규칙

목표는 프로젝트의 목적, 진행, 문제, 다음 일을 알맞은 기존 문서에 남겨 사람과 다음 AI가 쉽게 이어받게 하는 것이다. 짧은 자연어 보고는 이를 확인하는 보조 수단이다. 현재 제품 범위는 얇은 Independent Judgment Core와 `joeness-setup` 스킬 하나다. Windows PowerShell·Git 프로젝트·Codex에서의 동작만 출시 지원 범위로 주장한다.

아래 **필수 출시 항목**을 모두 실제 증거로 확인하고 사용자가 최종 출시를 승인해야 `정식 출시 완료`로 표기한다. 구현 완료, 검사 통과, 개인 설치, 사용자 수락, 기본 브랜치 반영은 서로 다른 상태다. 미완 항목을 지우거나 완료로 바꾸지 않는다. 범위를 줄이려면 사용자의 명시적 결정과 이유를 기록한다.

## 단계 순서와 상태

진행 순서는 **실제 프로젝트 운영 확인 → 사람 사용성 확인 → 가치·비용 판정 → 출시본 고정·배포**다. 현재 단계는 **2. 사람 사용성 확인(작업 중)**이다. 1단계의 한 실제 프로젝트·한 작업 운영 기준은 충족했지만 JOENESS 고유 성능이나 일반적 안정성을 입증한 것은 아니다. 단계를 닫기 전 해당 단계의 모든 필수 항목을 현재 파일·실제 결과로 다시 확인한다. 이전 대화나 오래된 평가 기록만으로 완료 처리하지 않는다. 단계가 열려 있으면 그것에 의존하는 다음 단계의 완료를 주장하지 않는다. 독립적으로 승인된 작업이나 준비는 진행할 수 있다.

맥락 저장·조회 후보의 별도 검증은 아래 **후속 시험 1→4** 순서로 진행한다. 이는 앞서 완료한 운영 사례를 취소하지 않지만, 이번 변경의 자동 연결·목표 모델·가치 판단을 이전 사례로 대신하지도 않는다. 앞 단계가 실패하거나 실행 불가이면 그 원인과 재시도 가능 조건을 남기고 뒤 단계의 성공을 선언하지 않는다.

각 항목은 `미완`, `작업 중`, `검증 대기`, `보류`, `완료`, `범위 제외` 중 하나로 관리한다. `[x]`는 검증을 마친 `완료`, `[ ]`는 완료 전 상태다. `검증 대기`와 `보류`는 필수 항목을 막는다. `범위 제외`는 항목을 삭제하지 않고 사용자의 명시적 결정·이유를 옆에 남긴다. 구현만 끝난 항목을 `완료`로 바꾸지 않는다. 단계 종료 보고에는 **완료된 항목·남은 항목과 상태·다음에 할 수 있는 일**을 먼저 적는다.

### 남은 필수 게이트 — 이 순서로 판정

1. **사람 사용성(작업 중):** 사용자가 실제 안내와 [머지멜론 A/B 인수인계](../evals/joeness-setup/runs/2026-09-29-mergedrop-feedback-ab/phase3-result.md)를 보고, 설정 위치·기록 위치·완료/미완/다음 행동을 혼자 파악할 수 있는지 확인한다. 막힌 표현과 계속 쓸 의향을 받는다. 모델의 자체 평가는 사람 평가로 대체하지 않는다. 아래 **필수 출시 항목 2**를 모두 마쳐야 통과다.
2. **가치·구성 결정(검증 대기):** 실제 작업 A/B에서 사실 누락·중복·잘못된 완료 선언·기록 분류와 시간/도구 비용을 비교하고, 프로젝트 연결과 Independent Judgment Core를 각각 유지·축소·제거할지 결정한다. 현재 연결의 고유 이득과 Core의 우월성은 모두 미입증이다. 정확한 토큰 수는 측정 가능할 때만 기록하며, 측정 불가를 절감으로 해석하지 않는다. 아래 **필수 출시 항목 3**과 **후속 시험 4**의 결정을 남겨야 통과다.
3. **출시본 안전 검증·승인(검증 대기):** 현재 후보의 개인 설치 `-Check: blocked` 원인을 안전하게 해소하고, 고정된 출시 commit에서 Windows 검사·깨끗한 설치/설정/해제·새 채팅 연결을 재검증한다. 알려진 제한과 해제 방법을 안내한 뒤 사용자 최종 승인을 받는다. 아래 **필수 출시 항목 4**를 모두 마치기 전에는 정식 출시를 선언하지 않는다.

머지멜론 동물 피드백 후보의 **시청각 선택 → 선택본 Android 실기기 검증 → 원본 반영 후 회귀 검사**는 그 게임의 기능 채택에 필수지만, JOENESS 출시 게이트는 아니다. 상세 체크리스트와 완료 판정은 게임 저장소의 `TASK.md`에서 관리한다. 두 후보를 자동 병합하거나 이전 동물 스킨의 기기 검증을 이번 효과의 검증으로 재사용하지 않는다. 전체 JOENESS/Bare 성능 A/B와 정확한 토큰 계측은 해당 우월성·절감 주장을 하려는 경우에만 추가 필수다. 이번 출시의 기본 약속이나 현재 프로젝트 연결 시험을 닫기 위한 반복 테스트로 만들지 않는다.

## 필수 출시 항목 — 순서대로

### 1. 실제 프로젝트에서 운영 확인 — 완료(한 프로젝트 범위)

### 3. 가치와 비용을 정직하게 판정 — 미완

2026-09-29 한 쌍의 [설정 제안 토큰 비교](../evals/joeness-setup/runs/2026-09-29-token-cost-ab/review-evidence.md)에서 Bare 69,589, JOENESS 79,741토큰으로 JOENESS가 10,152토큰(+14.59%) 더 썼다. 두 답변 모두 핵심 문서 역할을 찾았고 이 사례에서 고유한 정확도 개선은 입증되지 않았다. 단일 가상 프로젝트·단일 요청 결과라 일반 성능이나 실제 청구 비용으로 확대하지 않으며, 이 단계의 필수 항목은 계속 미완이다.
