# JOENESS 0.3 정식 출시 로드맵

기준: 2026-09-30. 이 문서는 **JOENESS 제품의 출시 준비**를 다룬다. `skills/joeness-setup/assets/ROADMAP.md`는 사용자의 *각 프로젝트*에 쓰는 참고 서식이며 이 문서와 다르다.

2026-09-28 베타 상태: `0.3.0-beta.1` 태그의 커밋 `6e8963c`가 `main`에 반영됐고 개인 설치 `-Check`는 `current`였다. 이는 **정식 출시 완료나 일반 사용자 검증 완료가 아니다.** 아래 미완 항목과 최종 사용자 승인은 그대로 남는다.

앞선 `0.3.0-beta.3-dev` 후보는 맥락 저장·조회 변경과 setup-only 배포 변경을 포함했다. 2026-09-30 개인 설치의 이전 Core를 정확한 이전 패키지로 해제하고 setup-only 후보를 설치해 `-Check: current`를 확인했다. 중립 프로젝트의 새 연결 적용·일상 기록·새 채팅 읽기도 제한된 범위에서 확인했다. [전환 증거](../evals/joeness-setup/runs/2026-09-30-setup-only-migration/review-evidence.md)와 [프로젝트 검증](../evals/joeness-setup/runs/2026-09-30-post-migration-project-route/review-evidence.md)을 보존한다. 기존 `0.3.0-beta.1` 평가 결과도 그대로 보존한다.

2026-09-30 **출시 컷 결정:** 사용자가 알려진 한계와 좁은 지원 범위를 수용하고 `0.3.0` 정식 출시를 승인했다. 새 A/B·토큰 절감·일반 성능 우월성 검증은 출시 조건에 추가하지 않는다. 이번 출시는 Windows PowerShell·Git·Codex의 setup-only 단일 스킬에 한정한다. 남은 기계적 게이트는 고정된 `0.3.0` 소스의 전체 로컬 검사, 원격 Windows CI, 안전한 개인 설치 `Check: current`, 태그 반영이다. 어느 하나라도 실패하면 완료를 선언하지 않는다.

2026-09-30 **정식 출시 완료:** [출시 증거](../evals/joeness-setup/runs/2026-09-30-v030-release/review-evidence.md)의 커밋 `89d33f8`, 태그 `JOENESS-v0.3.0`, 원격 Windows CI, 개인 설치 `Check: current`를 확인했다. 이 문서의 후속 기록 커밋은 출시 태그의 스킬·설치기 파일을 변경하지 않는다. 알려진 보고 분류 한계와 성능 미입증은 그대로 공개한다.

## 목표와 완료 규칙

목표는 프로젝트의 목적, 진행, 문제, 다음 일을 알맞은 기존 문서에 남겨 사람과 다음 AI가 쉽게 이어받게 하는 것이다. 짧은 자연어 보고는 이를 확인하는 보조 수단이다. `0.3.0`의 제품 범위는 `joeness-setup` 스킬 하나이며 전역 판단 Core는 없다. Windows PowerShell·Git 프로젝트·Codex에서의 동작만 출시 지원 범위로 주장한다.

아래 **필수 출시 항목**을 실제 증거와 사용자의 2026-09-30 출시 컷 결정에 따라 판정한다. 구현 완료, 검사 통과, 개인 설치, 사용자 수락, 기본 브랜치 반영은 서로 다른 상태다. 미완 항목을 지우거나 완료로 바꾸지 않는다. 범위를 줄일 때에는 사용자의 명시적 결정과 이유를 기록한다.

## 단계 순서와 상태

진행 순서는 **실제 프로젝트 운영 확인 → 사람 사용성 확인 → 가치·비용 판정 → 출시본 고정·배포**다. 네 단계는 위의 좁은 출시 범위에서 완료했다. 1단계는 한 실제 프로젝트·한 작업, 2단계는 한 사용자의 사용성 평가, 3단계는 제한된 A/B와 알려진 비용·정확도 한계 수용 범위에서 닫았다. 이는 JOENESS 고유 성능이나 일반적 안정성을 입증한 것이 아니다. 출시 후 새로운 문제나 개선은 별도 작업으로 다룬다.

맥락 저장·조회 후보의 별도 검증은 아래 **후속 시험 1→4** 순서로 진행한다. 이는 앞서 완료한 운영 사례를 취소하지 않지만, 이번 변경의 자동 연결·목표 모델·가치 판단을 이전 사례로 대신하지도 않는다. 앞 단계가 실패하거나 실행 불가이면 그 원인과 재시도 가능 조건을 남기고 뒤 단계의 성공을 선언하지 않는다.

각 항목은 `미완`, `작업 중`, `검증 대기`, `보류`, `완료`, `범위 제외` 중 하나로 관리한다. `[x]`는 검증을 마친 `완료`, `[ ]`는 완료 전 상태다. `검증 대기`와 `보류`는 필수 항목을 막는다. `범위 제외`는 항목을 삭제하지 않고 사용자의 명시적 결정·이유를 옆에 남긴다. 구현만 끝난 항목을 `완료`로 바꾸지 않는다. 단계 종료 보고에는 **완료된 항목·남은 항목과 상태·다음에 할 수 있는 일**을 먼저 적는다.

### 필수 게이트 판정

1. **사람 사용성(범위 한정 완료):** 사용자는 안내의 다섯 문서 역할을 충분하다고 평가했고, 실제 A/B에서 여섯 항목 요약을 선호하며 계속 사용할 의향을 밝혔다. 한 보고의 `이슈` 오분류와 긴 상세 설명은 알려진 한계로 남긴다. 독립적인 일반 사용자 검증은 주장하지 않는다.
2. **가치·구성 결정(완료):** 상시 Core 제거와 선택형 프로젝트 연결 유지가 결정됐다. 연결의 고유 정확도·속도 이득과 토큰 절감은 입증되지 않았으므로 출시 약속에 넣지 않는다. 추가 A/B는 이 출시의 게이트가 아니다.
3. **출시본 안전 검증·배포(완료):** `0.3.0`의 정확한 커밋에서 로컬 전체 검사·원격 Windows CI·개인 설치 전환 및 `Check: current`·태그 반영을 확인했다. 이전 후보의 새 채팅 증거는 범위를 표시해 재사용하며 문서·버전 식별자 변경만으로 같은 행동 시험을 반복하지 않았다.

머지멜론 동물 피드백 후보의 **시청각 선택 → 선택본 Android 실기기 검증 → 원본 반영 후 회귀 검사**는 그 게임의 기능 채택에 필수지만, JOENESS 출시 게이트는 아니다. 상세 체크리스트와 완료 판정은 게임 저장소의 `TASK.md`에서 관리한다. 두 후보를 자동 병합하거나 이전 동물 스킨의 기기 검증을 이번 효과의 검증으로 재사용하지 않는다. 전체 JOENESS/Bare 성능 A/B와 정확한 토큰 계측은 해당 우월성·절감 주장을 하려는 경우에만 추가 필수다. 이번 출시의 기본 약속이나 현재 프로젝트 연결 시험을 닫기 위한 반복 테스트로 만들지 않는다.

### 시험 1. 새 프로젝트의 자동 연결 — 완료(한 시험 채팅의 관찰 범위)

- [x] **완료:** 새 앱 채팅의 요청에는 JOENESS·스킬 경로·읽기 순서·보고 형식을 넣지 않았다. 현재 ROADMAP/TASK·Product·코드·관련 Issue와 오래된 HANDOFF를 읽고 최신 상태·승인 범위·다음 행동을 구분했다. 무관한 DESIGN은 읽지 않았고 파일을 쓰지 않았다. 이는 [자동 연결과 일치하는 한 채팅의 행동 증거](../evals/joeness-setup/runs/2026-09-29-context-routing-follow-up/phase1-app-result.md)이지 주입 내부의 직접 증명이나 일반 성공률은 아니다.
- [x] **완료:** 앞선 CLI의 읽기 차단과 앱 시험의 통과를 모두 보존했다. 시험용 연결문에 평가자가 남긴 서식 안내·중복 문구가 있었으므로 정상 설정 제안의 간결함은 이 시험으로 판정하지 않는다. 시험 2는 이 범위를 유지하고 진행한다.

### 시험 2. 지정 모델 행동 — 완료(요청 런타임·세 사례의 한정된 행동 범위)

- [x] **완료(사전 행동 기준):** 현재 상태 우선, 상충 방향 미발명·자동 재편 금지, 부분 쓰기 경계를 세 fresh 세션에서 비교했다. 2C는 코드·테스트 완료와 TASK 쓰기 실패를 분리했지만, 다음 행동을 JSON으로 적어 기록 복구를 우선하지 않았고 ISSUES에 작업 상태가 일부 섞였다. 이는 기록·인수인계 품질의 미확인/보완 후보로 남기며 독립 정확도나 고유 가치를 주장하지 않는다.

### 시험 3. 실제 업무와 프로젝트 연결 A/B 비교 — 완료(한 쌍의 한정된 결과)
