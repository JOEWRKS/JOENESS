# JOENESS 0.3 정식 출시 로드맵

기준: 2026-09-28. 이 문서는 **JOENESS 제품의 출시 준비**를 다룬다. `skills/joeness-setup/assets/ROADMAP.md`는 사용자의 *각 프로젝트*에 쓰는 참고 서식이며 이 문서와 다르다.

2026-09-28 베타 상태: `0.3.0-beta.1` 태그의 커밋 `6e8963c`가 `main`에 반영됐고 개인 설치 `-Check`는 `current`였다. 이는 **정식 출시 완료나 일반 사용자 검증 완료가 아니다.** 아래 미완 항목과 최종 사용자 승인은 그대로 남는다.

현재 `0.3.0-beta.2-dev` 소스 후보에는 이후의 맥락 저장·조회 변경도 포함된다. 앞선 단계별 로드맵 연결 후보를 2026-09-29 개인 설치에 갱신한 기록은 있지만, **현재 소스**의 개인 설치 `-Check`는 manifest 불일치로 `blocked`이다. 현재 후보를 설치·출시 승인하거나 원격 배포하지 않았다. 기존 `0.3.0-beta.1` 평가 결과는 그대로 보존한다.

## 목표와 완료 규칙

목표는 프로젝트의 목적, 진행, 문제, 다음 일을 알맞은 기존 문서에 남겨 사람과 다음 AI가 쉽게 이어받게 하는 것이다. 짧은 자연어 보고는 이를 확인하는 보조 수단이다. 현재 제품 범위는 얇은 Independent Judgment Core와 `joeness-setup` 스킬 하나다. Windows PowerShell·Git 프로젝트·Codex에서의 동작만 출시 지원 범위로 주장한다.

아래 **필수 출시 항목**을 모두 실제 증거로 확인하고 사용자가 최종 출시를 승인해야 `정식 출시 완료`로 표기한다. 구현 완료, 검사 통과, 개인 설치, 사용자 수락, 기본 브랜치 반영은 서로 다른 상태다. 미완 항목을 지우거나 완료로 바꾸지 않는다. 범위를 줄이려면 사용자의 명시적 결정과 이유를 기록한다.

## 단계 순서와 상태

진행 순서는 **실제 프로젝트 운영 확인 → 사람 사용성 확인 → 가치·비용 판정 → 출시본 고정·배포**다. 현재 단계는 **2. 사람 사용성 확인(작업 중)**이다. 1단계의 한 실제 프로젝트·한 작업 운영 기준은 충족했지만 JOENESS 고유 성능이나 일반적 안정성을 입증한 것은 아니다. 단계를 닫기 전 해당 단계의 모든 필수 항목을 현재 파일·실제 결과로 다시 확인한다. 이전 대화나 오래된 평가 기록만으로 완료 처리하지 않는다. 단계가 열려 있으면 그것에 의존하는 다음 단계의 완료를 주장하지 않는다. 독립적으로 승인된 작업이나 준비는 진행할 수 있다.

맥락 저장·조회 후보의 별도 검증은 아래 **후속 시험 1→4** 순서로 진행한다. 이는 앞서 완료한 운영 사례를 취소하지 않지만, 이번 변경의 자동 연결·목표 모델·가치 판단을 이전 사례로 대신하지도 않는다. 앞 단계가 실패하거나 실행 불가이면 그 원인과 재시도 가능 조건을 남기고 뒤 단계의 성공을 선언하지 않는다.

각 항목은 `미완`, `작업 중`, `검증 대기`, `보류`, `완료`, `범위 제외` 중 하나로 관리한다. `[x]`는 검증을 마친 `완료`, `[ ]`는 완료 전 상태다. `검증 대기`와 `보류`는 필수 항목을 막는다. `범위 제외`는 항목을 삭제하지 않고 사용자의 명시적 결정·이유를 옆에 남긴다. 구현만 끝난 항목을 `완료`로 바꾸지 않는다. 단계 종료 보고에는 **완료된 항목·남은 항목과 상태·다음에 할 수 있는 일**을 먼저 적는다.

- [x] 가상 프로젝트의 새 세션에서 설정 연결, 장기 기록, 인수인계와 실제 코드 수정 검증. 짧은 여섯 항목 보고는 사용자에게 이전보다 읽기 쉽다는 평가를 받았다. 한정된 결과와 실패 기록은 [평가 목록](../README.md#구현과-검증)과 [최근 비교](../evals/joeness-setup/runs/2026-09-27-plain-language-report/review-evidence.md)에 남긴다.

## 맥락 저장·조회 후보 후속 시험 — 순서대로

기준 소스: `codex/joeness-context-routing`의 `52b128c`. [구현 검증](../evals/joeness-setup/runs/2026-09-29-context-routing/review-evidence.md)은 Windows 계약·설정 안전성 통과와 **스킬을 직접 읽게 한** 가상 행동 시험을 증명한다. [시험 1 결과](../evals/joeness-setup/runs/2026-09-29-context-routing-follow-up/phase1-result.md): 연결 적용은 통과했지만 새 실행의 파일 읽기가 환경 정책에 차단되어 **시험 1 보류**다. 성공·실패·실행 불가·미검증을 섞지 않는다.

### 시험 1. 새 프로젝트의 자동 연결 — 보류

- [ ] **작업 중:** 실제 실행 경로가 `gpt-6-astra` / `xhigh`와 실행 식별자를 기록할 수 있는지 확인한다. 이전 `codex-cli 0.146.0`은 모델 응답 전 HTTP 400으로 실패했다. 새 `0.158.0-alpha.2.1`에서는 해당 모델·노력을 요청한 세션이 응답하고 스레드·사용량을 남겼지만 내부 모델 식별자는 별도 노출되지 않았다. 다른 모델 결과나 요청 설정만으로 정확한 런타임 정체성을 단정하지 않는다.
- [ ] **검증 대기:** 신선한 세션에서 현재 상태 우선·단일 기록 위치·상충 권위의 미발명·한 신호에서 재편 강요 없음·부분 쓰기 경계를 사전 기대와 비교한다. 첫 명확한 결과를 보존하고 실패를 수정했다면 같은 영향 사례만 새 세션에서 재검증한다.

### 시험 3. 실제 업무와 Bare/JOENESS 비교 — 검증 대기

- [ ] **검증 대기:** 시험 1·2의 경계가 확인된 뒤 같은 승인 범위·시작 상태의 실제 다단계 업무를 두 조건에서 비교한다. 사용자 소유 실프로젝트에는 동의 없이 평행한 작업·기록을 만들지 않는다. 필요하면 분리된 가상 Git 프로젝트로 먼저 연습하고 실제 프로젝트/업무 선택은 별도 승인받는다.
- [ ] **검증 대기:** 완료·미완·원인·다음 행동의 새 담당자 복원 정확도, 누락·중복 기록, 잘못된 완료 선언, 불필요한 절차, 입력/출력 토큰과 관찰 시간을 함께 기록한다. 사람 읽기 평가는 모델 채점과 분리한다. 소수 사례로 일반 토큰 절감이나 성능 우월을 주장하지 않는다.

### 시험 4. 유지·축소·수정 판정 — 검증 대기

- [ ] **검증 대기:** 1~3의 통과·실패·미실행을 따로 보고한다. 고유 이득 없이 읽기·쓰기·시간 비용만 늘면 규칙 축소를 우선 검토하고, 실제 실패는 가장 작은 수정과 영향 범위 재시험으로 다룬다. Product·Design 권위나 개인 설치는 판정만으로 바꾸지 않는다.

## 필수 출시 항목 — 순서대로

### 1. 실제 프로젝트에서 운영 확인 — 완료(한 프로젝트 범위)

- [x] 사용자가 허용한 **실제 Git 프로젝트 한 곳**과 문서 변경 범위를 정한다. 기존 Product·승인 Design·작업 규칙을 우선하고, 실험용 문서나 새 기능을 임의로 만들지 않는다.
- [x] 설치와 프로젝트 연결을 구분해 확인한다. 첫 설정안 제시 → 사용자 승인 → 적용 → 새 채팅에서 지침 전달 확인을 실제 파일·상태로 증명한다.
- [x] 승인된 실제 업무 **한 건**의 현재 상태 → 진행·검증 → 새 채팅 인수인계를 확인한다. 목표/필수 완료 기준은 ROADMAP 역할, 수행·검증은 TASK 역할, 재발 가치가 있는 문제는 ISSUES 역할에 기록되는지 본다. 머지멜론처럼 한 파일이 로드맵과 작업을 함께 맡으면 그 원본을 재사용한다. 시험을 위해 가짜 업무나 불필요한 문서를 만들지 않는다. DungeonGameV3의 실제 저주 보상 추천 수정·검증·새 채팅 인수인계로 이 운영 절차를 확인했다. 인수인계 품질은 다음 항목에서 별도 판정한다.
- [x] 새 채팅의 담당자가 이전 대화 없이 현재 파일만으로 **완료된 일·남은 일·문제 원인·다음 행동**을 정확히 설명하는지 확인한다. 오래된 기록보다 현재 파일·Git 상태를 우선해야 한다. 실패와 수정은 보존한다. DungeonGameV3의 원인을 명시적으로 요구한 fresh 읽기 전용 재검증에서 충족했으며, 더 모호한 앞선 요청의 원인 누락도 보존한다. 이 결과는 JOENESS 고유 효과의 증거가 아니다.

첫째·둘째 항목의 범위와 실패·수정 내역: [머지멜론 실제 프로젝트 검증](../evals/joeness-setup/runs/2026-09-27-mergedrop-real-pilot/review-evidence.md). `0.1.13` 점검의 새 채팅 인계는 정확했지만 사용자가 원래 필요로 한 개발 업무가 아니었다. 따라서 셋째·넷째 항목은 **실제 기능 작업 후 재확인**한다. 게임의 출시 준비가 끝났다는 뜻도 아니다.

### 2. 사람이 실제로 쓸 수 있는지 확인 — 작업 중

2026-09-29 보고 기준 보정: 첫 여섯 항목은 **쉬운 단어 또는 짧은 문장으로 사실 하나씩**, 필요한 원인·근거·검증 한계만 상세 보고에 둔다. 글자 수 상한은 두지 않는다. 기존 스킬의 보고 지침을 추가가 아닌 교체로 줄였으며, 실제 사람 읽기 평가는 아직 미완이다.

2026-09-29 [보고 형식 편향 A/B](../evals/joeness-setup/runs/2026-09-29-format-bias/review-evidence.md)와 [보강 2쌍](../evals/joeness-setup/runs/2026-09-29-format-bias/follow-up-evidence.md): 고정 사실 5건에서 자유 형식·여섯 항목 모두 중대한 사실 오류 0/5였다. 여섯 항목 때문에 없는 해결을 만들거나 단순 질문에 작업 보고를 붙인 사례는 없었다. 일부 상세 보고는 반복되어 다섯 답변의 출력 토큰 합계가 자유 형식보다 약 13% 많았다. 이 결과는 실제 장기 협업 성능이나 사람이 읽는 편의의 판정이 아니므로 아래 항목은 미완이다. 기존 규칙에 반복 억제가 있어 새 규칙은 추가하지 않았다.

2026-09-29 실제 [프로젝트 연결 시험](../evals/joeness-setup/runs/2026-09-29-format-bias/project-connection-evidence.md)은 위 텍스트 A/B의 한계를 드러냈다. 2026-09-29 후속 [설정안 제안 시험](../evals/joeness-setup/runs/2026-09-29-format-bias/setup-proposal-forward-evidence.md)은 갱신된 개인 설치에서 스킬을 실제로 읽고 기존 문서 연결안을 제안만 했다. 파일 변경은 없었고 `해결=검증된 수정만`, 미검증·수락 분리, 단순 질문 예외는 제안 본문에 남았다. 다만 최종 보고 규칙 문장에 `이슈=발생한 문제`를 직접 풀어 쓰지는 않아 사전 기준의 모든 항목은 부분 충족이다. 이 단일 제안은 일반적인 제안 품질·사람 사용성을 입증하지 않는다.
