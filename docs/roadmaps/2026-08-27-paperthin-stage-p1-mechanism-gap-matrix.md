## 판정 기준

- `ALREADY_COVERED`: 현재 활성 JOENESS 계약이 같은 실패 모드를 필요한 권한·증거·중단 경계에서 이미 막는다. Paperthin의 별도 형식을 추가해도 핵심 동작 차이가 없다.
- `GAP_CANDIDATE`: 현재 JOENESS에 부분 중복은 있지만 Paperthin 메커니즘의 고유 trigger/reflex/proof 중 하나 이상이 활성 계약에 없다. 이는 조사 후보일 뿐 채택 근거가 아니다.
- `CONFLICT`: 메커니즘의 핵심 동작이 현재 JOENESS의 권한, 단일-writer, 증거, 최소 영속 상태 또는 중단 경계와 양립하지 않는다.
- `NO_EVIDENCE`: pinned source만으로 메커니즘이나 현재 JOENESS 대비를 판정할 수 없다.

Source fact는 pinned Paperthin 파일에 직접 적힌 동작만 요약한다. JOENESS inference는 별도 열에서 pinned JOENESS 계약과 비교한 해석이며 Paperthin이 JOENESS의 실제 성능이나 필요성을 증명한다는 뜻이 아니다.

## P1 result and boundary

- 분류 합계: `ALREADY_COVERED=1`, `GAP_CANDIDATE=4`, `CONFLICT=0`, `NO_EVIDENCE=0`.
- `GAP_CANDIDATE`는 mechanism-level의 빈자리만 뜻한다. 실제 프로젝트에서 비용 있는 실패가 있었는지, 반복되는지, 어느 통합 형태가 맞는지는 P2/P3 전에는 `UNVERIFIED`다.
- 이 단계는 JOENESS rule, Core, skill, evaluator, installer 또는 manifest를 변경하지 않는다. Paperthin code/text를 JOENESS runtime에 복사하거나 설치하지 않았다.
- `re0-memo`의 `ALREADY_COVERED`는 JOENESS 전체 회고 품질이나 모든 프로젝트에서의 일반 행동을 증명하지 않는다. pinned active contract와 한 repository-preserved retrospective가 WATCH의 핵심 escalation guard를 이미 표현한다는 좁은 판정이다.
