# JOENESS 0.2 사용 안내

설치와 프로젝트 설정은 별개입니다. 설치는 얇은 Core와 joeness-setup 스킬만
준비하며, 프로젝트 문서 5개를 자동 생성하지 않습니다.

## 처음 사용하기

1. 작업할 프로젝트를 Codex에서 열고 새 세션을 시작합니다.
2. `$joeness-setup으로 이 프로젝트 설정안을 보여줘.`라고 요청합니다.
3. 연결할 기존 문서, 필요한 새 문서, 기록 범위를 확인한 뒤
   `이대로 적용하고, 작업 결과와 문제 해결 내용을 기록해줘.`라고 승인합니다.

## 문서 5개의 역할

아래 이름은 역할별 기본 예시입니다. 기존 문서가 있으면 이름과 경로를 그대로
사용하고, 필요한 역할에 문서가 없을 때만 생성안을 제안합니다.

| 문서 | 역할 | 언제 사용하는가 |
|---|---|---|
| AGENTS.md | 작업 규칙, 원본 문서 위치, 동의한 기록 범위를 연결하는 안내판 | 작업 시작·재개 때 에이전트가 참고 |
| ROADMAP.md | 목표·우선순위·명시적으로 결정한 방향 | 다음 목표나 우선순위를 결정할 때; Product 원본을 대체하지 않음 |
| TASK.md | 현재 승인된 작업 범위·진행·실제 검증 결과·남은 일 | 진행 상황 확인과 이어서 작업할 때 |
| ISSUES.md | 문제 증상·확인된 원인·해결·검증·유효한 우회책 | 같은 문제가 재발하거나 과거 해결책을 찾을 때 |
| DESIGN.md | 디자인 원본과 승인 사항의 연결 | 디자인 관련 작업이 있을 때; 제안·검증·사용자 승인은 구분 |

설정이 끝나면 실제 연결·생성·수정한 경로와 각 역할, 사용하지 않은 역할을
알려줍니다. 원래 문서와 새로 만든 문서는 구분하며, 디자인 작업이 없으면
DESIGN.md를 억지로 만들지 않습니다.

## 설정 후에는 평소처럼 요청하기

- 작업: `로그인 오류 고쳐줘.`
- 재개·현황: `어디까지 했는지 알려주고, 남은 작업을 이어서 진행해.`
- 과거 해결 조회: `이전에 이 오류를 어떻게 해결했는지 찾아봐.`
- 이번 작업 기록 제외: `코드는 고치되 이번 작업은 문서에 기록하지 마.`
- 지속적인 기록 중지: `자동 기록만 중지하고, 문서 위치 연결은 남겨줘.`
- 프로젝트 해제: `이 프로젝트에서 JOENESS 연결을 해제해줘.`

매 작업마다 setup을 다시 호출할 필요는 없습니다. 에이전트가 작업하면서
동의한 범위의 사실을 기록하는 것이며, 별도 백그라운드 기록기는 없습니다.
질문·의견만으로 문서를 갱신하지 않습니다. 기록 중지, 프로젝트 연결 해제,
패키지 제거는 서로 다릅니다. 연결을 해제해도 일반 프로젝트 문서는 남습니다.
