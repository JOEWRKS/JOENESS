# JOENESS 0.3 사용 안내

## 핵심

JOENESS는 목표, 한 일, 문제와 다음 일을 프로젝트의 알맞은 문서에 남겨 다음 담당자가 이어받기 쉽게 돕습니다. 설치되는 도구는 프로젝트 문서 연결용 `joeness-setup` 하나입니다. 전역 판단 지침은 설치하지 않습니다.

## 설계 목적

기존 문서를 먼저 사용하고, 같은 사실은 주된 원본 한 곳에 기록합니다. 다른 문서에는 필요한 위치만 연결합니다. 작업을 했다는 사실, 필수 검증의 완료, 사용자의 수락은 구분합니다. JOENESS는 보이지 않는 곳에서 계속 일하는 프로그램이 아닙니다.

## 사용법

### 새 프로젝트

1. Git 프로젝트를 Codex에서 열고 새 채팅에서 `이 프로젝트에 JOENESS 설치해줘.`라고 요청합니다. 원하면 `$joeness-setup`을 명시해도 됩니다.
2. 새로 만들거나 바꿀 파일, 문서별 역할과 평소 기록 범위를 먼저 확인합니다. 이 요청만으로 파일을 바꾸거나 개인 설치를 갱신하지 않습니다.
3. 제안이 맞으면 `이대로 적용해줘.`라고 승인합니다. 적용 후 실제로 만든 파일과 수정·연결한 파일을 구분해 보고받습니다.

새 프로젝트라도 문서 다섯 개를 자동 생성하지 않습니다. 현재 자동 연결 도구는 명시한 Git 루트에서 작동하며, Git이 없는 폴더를 임의로 초기화하지 않습니다.

### 기존 프로젝트

1. 같은 문장으로 설정을 요청합니다. 현재 `AGENTS.md`와 제품·계획·작업·문제·디자인 원본을 먼저 확인합니다.
2. 기존 이름과 경로를 재사용하는 변경안을 검토합니다. 필요한 기록 자리가 없는 경우에만 새 문서를 제안합니다. 기존 내용을 자동 재편하거나 승인된 제품·디자인 기준을 바꾸지 않습니다.
3. 승인한 범위만 적용합니다. 긴 지침이나 소유권 충돌로 안전하게 연결할 수 없으면 변경 없이 그 이유를 보고받습니다.

설정에 성공하면 프로젝트 `AGENTS.md`에 짧은 연결 구역이 들어갑니다. `AGENTS.md`가 없었다면 생성되고, 있었다면 기존 본문은 보존합니다. `.joeness/setup-state.json`은 연결 구역의 적용 기준을 보관합니다. 이 상태 파일은 업무 기록이나 사용자 승인 증거가 아닙니다. 개인 도구 설치와 프로젝트 연결은 별개이며, 매 작업마다 setup을 다시 요청할 필요는 없습니다.

### 문서 구조와 책임

아래 이름은 기본 예시입니다. 기존 문서가 있으면 실제 파일명과 경로를 사용하고, 다섯 파일을 한꺼번에 만들지 않습니다.

| 역할 | 담는 내용 | 주로 보는 때 |
|---|---|---|
| `AGENTS.md` | 짧은 작업 안내, 원본 위치, 동의한 기록 범위 | 프로젝트 시작 |
| `ROADMAP.md` | 목표·구현 순서, 현재 단계, 필수 항목의 상태·완료 기준 | 새 작업·재개·단계 완료 판단 |
| `TASK.md` | 승인된 작업의 진행·결과·검증·남은 일 | 진행 확인·인수인계 |
| `ISSUES.md` | 재발할 문제의 증상·원인·해결·우회책 | 문제 조사·재발 확인 |
| `DESIGN.md` | 디자인 원본·승인 범위·미승인 부분 | 시각 작업이 있을 때 |

`PRODUCT.md` 등 기존 제품 기준은 이 다섯 역할 밖에 있을 수 있습니다. JOENESS가 새 여섯 번째 필수 문서로 만들거나 로드맵으로 대체하지 않습니다. 디자인 작업이 없으면 `DESIGN.md`도 억지로 만들지 않습니다.

RACI는 문서에 붙이는 고정 순위가 아니라 사람의 책임을 나타냅니다.

- **수행(R):** 담당자나 AI가 승인된 작업을 실행하고 확인된 사실을 기록합니다.
- **결정(A):** 권한 있는 사용자·프로젝트 책임자가 목표·범위 변경과 사용자 수락을 결정합니다. 디자인 변경은 프로젝트가 정한 승인권자가 승인합니다.
- **참여(C):** 제품·디자인 담당자가 실제로 있을 때 관련 판단에 참여합니다.
- **공유(I):** 다음 담당자에게 확정 상태와 남은 일을 알립니다.

없는 담당자를 만들어 내거나 일상 기록마다 재승인을 요구하지 않습니다.

읽기는 작업에 따라 달라집니다. 새 작업·재개는 현재 `ROADMAP` 단계와 `TASK`부터, 문제 재발은 관련 `ISSUES`와 현재 구현부터, 시각 작업은 승인된 `DESIGN`과 제품 기준부터 확인합니다. 관계없는 문서를 매번 모두 읽지 않습니다. 현재 코드·Git·실제 대상은 오래된 진행 설명보다 현재 상태의 근거가 되지만, 승인된 범위와 디자인을 임의로 바꾸지는 않습니다.

로드맵에 필수 단계가 있다면 미완·작업 중·검증 대기·보류는 남은 일입니다. 개별 작업이 끝나도 필수 항목을 확인하기 전에는 단계를 완료라고 하지 않습니다. 범위 제외는 권한 있는 결정과 이유를 남기는 상태이지 완료 표시가 아닙니다.

### 평소 작업과 보고

설정 뒤에는 평소처럼 요청합니다.

- 작업: `로그인 오류 고쳐줘.`
- 재개: `끝난 일과 남은 일을 확인하고 이어서 진행해.`
- 과거 문제: `이전에 이 오류를 어떻게 해결했는지 찾아봐.`
- 이번 기록 제외: `코드는 고치되 이번 작업은 문서에 기록하지 마.`
- 기록 중지: `자동 기록만 중지하고 문서 위치 연결은 남겨줘.`
- 프로젝트 해제: `이 프로젝트에서 JOENESS 연결을 해제해줘.`

실제 작업이나 인수인계 뒤에는 먼저 짧은 여섯 항목으로 알립니다. 단어와 짧은 자연어 문장으로 핵심을 쓰고, 원인·검증 근거·승인 경계가 꼭 필요할 때만 상세 보고를 덧붙입니다. 질문만 받은 때에는 이 형식을 강제하지 않습니다.

- 작업: 예약 오류 수정.
- 업데이트 파일: 예약 기능, 자동 검사, 작업 기록.
- 이슈: 취소하면 예약 기록이 사라졌음.
- 해결: 취소 처리 수정과 검사 통과.
- 남은 문제: 실제 행사장 기기 확인 전.
- 다음 작업: 행사장 기기에서 예약·취소 확인.

`이슈`는 발견한 문제, `해결`은 실제로 고쳐 확인한 내용, `남은 문제`는 미해결이거나 검증되지 않은 일입니다. 해당 내용이 없으면 `이슈: 없음`, `남은 문제: 없음`이라고 씁니다. 바꾸지 않은 파일이나 확인하지 않은 해결을 보고하지 않습니다.

## 주의

질문·의견만으로 문서를 갱신하지 않습니다. 평소 기록은 설정 때 동의한 범위에서 실제 작업을 할 때만 남기며, 별도 백그라운드 기록기는 없습니다. 한 사실을 여러 문서에 반복해 쓰지 않고 주된 기록 위치를 연결합니다.

기존 문서가 복잡해도 자동으로 옮기거나 줄이지 않습니다. 실제 지침 잘림이나 상태 조회 오류가 확인되거나, 중복·충돌·불필요한 상시 읽기 등 문제가 함께 발견되면 근거와 작은 변경안을 먼저 보여줍니다. 사용자 승인 없이 원본을 이동·삭제하지 않습니다.

기록 중지는 문서 위치 안내를 남기고 기록 범위만 바꿉니다. 프로젝트 연결 해제는 확인된 JOENESS 관리 구역만 제거하며 일반 문서는 남깁니다. 개인 패키지 제거는 별도 작업이고 프로젝트 연결을 일괄 해제하지 않습니다. 설치나 연결을 바꾼 뒤 이미 열린 채팅에는 새 안내가 즉시 반영되지 않을 수 있으므로 새 채팅에서 확인합니다.

JOENESS는 토큰 절감, 모든 환경에서의 자동 적용, 다른 도구보다 높은 작업 정확도를 보장하지 않습니다. 현재 확인한 범위와 남은 검증은 저장소의 `README.md`와 `docs/ROADMAP.md`를 참고합니다.
