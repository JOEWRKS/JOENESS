# JOENESS 사용 안내

## 핵심

JOENESS는 목표를 단계별 로드맵으로 관리하고, 작업 결과와 문제를 정해진 문서에 나눠 남깁니다. 작업 뒤에는 여섯 항목으로 먼저 보고합니다.

설치되는 도구는 프로젝트 설정용 `joeness-setup` 하나입니다. 전역 판단 지침은 설치하지 않습니다. 개인 도구 설치만으로 프로젝트 파일을 자동 생성하지 않습니다.

## 설계 목적

계획이 흩어지고, 끝난 일과 남은 일이 뒤섞이는 문제를 줄이는 것이 목적입니다. 상세 사실은 한 곳에 기록하고 필요한 곳에서 연결합니다. 구현 완료·검증 완료·사용자 수락은 구분합니다.

## 사용법

### 새 프로젝트

1. Git 프로젝트에서 `이 프로젝트에 JOENESS 설치해줘.` 또는 `$joeness-setup` 요청.
2. 다섯 기준 파일, 만들거나 바꿀 내용, 평소 기록 범위 확인.
3. `이대로 적용해줘.` 승인 후 적용 결과 확인.

ROADMAP은 기본 운영 문서입니다. 목표가 미정이면 결정 대기로 표시합니다. 없는 목표·문제·디자인 승인을 만들어 채우지 않습니다. Library는 저장할 자료가 생길 때 만듭니다.

### 기존 프로젝트

1. 같은 문장으로 설정 요청. 현재 목표·계획·작업 결과·근거 확인.
2. 기존 내용을 표준 문서로 옮기거나 정리할 변경안 확인. 이미 맞는 내용은 유지.
3. 승인 후 적용. 이전 자료의 근거·이력은 보존하고 현재 관리는 새 원본으로 단일화.

특정 기능 계획만으로 프로젝트 전체 로드맵을 대신하지 않습니다. 이전 문서를 삭제하거나 승인 기준을 바꾸는 일은 설정 요청만으로 허용되지 않습니다. 필요한 정리가 승인되지 않았다면 설정 미완료로 알립니다.

Git이 없는 폴더는 자동 초기화하지 않고 변경안만 제시합니다. 관리 구역 충돌이나 긴 지침 때문에 안전하게 연결할 수 없으면 해당 문제부터 보고합니다.

### 문서 구조와 책임

| 파일 | 담당 정보 | 넣지 않는 내용 |
|---|---|---|
| AGENTS.md | 작업 규칙, 문서 위치, 읽기·갱신 순서 | 과거 작업 전문, 진행 현황 |
| ROADMAP.md | 프로젝트 목표, 단계 순서, 필수 검증, 상태·다음 작업 | 공통 운영 규칙, 조사·작업 전문 |
| TASK.md | 로드맵 항목별 수행 결과와 검증 근거 | 별도의 단계 완료표 |
| ISSUES.md | 미해결 문제, 우회책, 남은 위험, 해결 조건 | 모든 미완성 기능 |
| DESIGN.md | 전체 시각 규칙, 승인 원본·범위, 미승인 변경 | 제품 목표, 진행 현황 |
| Library/ | 주제별 조사·참고·기술 자료 | 현재 진행표, 승인 결정의 대체본 |

다섯 파일은 프로젝트의 기준입니다. 해당 내용이 없으면 없음·미정·해당 없음으로 표시합니다. `PRODUCT.md` 등 기존 제품 기준은 별도 원본으로 유지하며 새 필수 파일로 만들지 않습니다. 기존 상세 자료는 필요한 위치를 연결합니다.

Library는 날짜보다 주제로 묶습니다. 작은 조사 하나마다 파일을 늘리지 않고 같은 주제의 절에 추가합니다. 출처·확인일·사실과 추론·한계를 남깁니다. 일회성 검토 결과는 TASK로 충분할 수 있습니다.

**책임:** 작업 담당자(R)가 결과·검증과 영향받은 상태를 갱신합니다. 권한 있는 사용자나 책임자(A)가 목표·범위·승인을 결정합니다. 관련 담당자가 있을 때만 의견(C)을 받고 다음 담당자에게 결과(I)를 공유합니다. 문서 자체에 사람의 승인권을 부여하지 않습니다.

**읽는 순서:** 새 작업은 ROADMAP부터, 문제 조사는 ISSUES와 실제 대상부터, 시각 작업은 작업 범위와 DESIGN부터, 조사는 관련 Library부터 확인합니다. 완료 판단은 ROADMAP의 필수 조건과 실제 근거를 대조합니다. 항상 전부 읽지는 않습니다.

**기록 방식:** 상세 사실은 담당 문서 한 곳에, 다른 문서에는 짧은 상태와 링크만 기록합니다. 처음부터 간결하게 쓰되 원인·근거·미확인·승인 경계는 남깁니다. 검증 기준은 ROADMAP, 실제 결과는 TASK, 남은 위험은 ISSUES에 둡니다. 우회책이 생겨도 문제가 완전히 해결된 것으로 처리하지 않습니다.

### 평소 요청과 보고

설정은 매 작업마다 다시 할 필요가 없습니다.

- 작업: `로그인 오류 고쳐줘.`
- 재개: `로드맵의 다음 작업 이어서 진행해.`
- 조회: `이전에 이 오류를 어떻게 해결했는지 찾아봐.`
- 이번 기록 제외: `코드는 고치되 이번 작업은 문서에 기록하지 마.`
- 기록 중지: `자동 기록만 중지하고 문서 위치 연결은 남겨줘.`

작업·인수인계 보고는 여섯 항목을 먼저 사용합니다. 단어와 짧은 문장 중심이며, 상세 설명은 필요한 근거·한계만 뒤에 붙입니다.

- 작업: 예약 오류 수정.
- 업데이트 파일: 예약 기능, 검사, 작업 기록.
- 이슈: 취소 시 예약 내역 삭제.
- 해결: 취소 처리 수정·확인.
- 남은 문제: 행사장 기기 확인 전.
- 다음 작업: 실제 기기에서 예약·취소 확인.

이슈는 발생한 문제, 해결은 확인된 수정, 남은 문제는 미해결·미검증을 뜻합니다. 내용이 없으면 `이슈: 없음`, `남은 문제: 없음`처럼 표시합니다. 단순 질문에는 보고 형식을 강제하지 않습니다.

## 주의

- 개인 설치와 프로젝트 설정은 별개입니다. 적용 후 실제 생성·변경 파일과 기록 범위를 보고받으세요.
- `.joeness/setup-state.json`은 AGENTS 연결 구역의 적용 기준입니다. 업무 기록이나 승인 증거가 아닙니다.
- 연결 정상, 문서 적합, 새 채팅의 지침 전달, 작업 결과 검증은 다른 확인입니다. 연결 성공만으로 모두 검증됐다고 하지 않습니다.
- 단계의 필수 검증이 남으면 완료가 아닙니다. 독립적으로 승인된 작업까지 중단할 필요는 없습니다.
- 전문 검증이 필요한 작업은 [결과 검사](review-gate.md)를 연결할 수 있습니다. 누락·실패·오래된 근거는 해당 완료 판정을 막습니다. 시각 검사 통과와 사용자 수락은 별개이며, 파일 직접 수정이나 말로만 하는 완료 선언까지 자동 차단하지는 않습니다.
- 질문·의견만으로 기록하지 않습니다. 기록은 동의한 범위에서만 하며 백그라운드 갱신기는 없습니다.
- 비밀번호·인증키·불필요한 개인정보는 기록하지 않습니다. 필요한 뜻만 가려서 요약하고, 허용된 원본 위치를 연결합니다.
- 여러 담당자가 같은 기록을 고칠 때는 통합 담당 한 명이 최신 내용을 확인해 반영합니다. 충돌한 부분만 보류하며 자동 잠금 기능은 없습니다.
- `이 프로젝트에서 JOENESS 연결을 해제해줘.`는 소유한 연결 구역만 제거합니다. 일반 문서와 이력은 남습니다. 개인 도구 제거는 별도입니다.
- 설치·설정 변경 뒤 기존 채팅이 새 지침을 자동으로 받았다고 가정하지 않습니다. 새 채팅에서 별도로 확인합니다.
- 토큰 절감이나 모든 환경의 정확도 향상은 보장하지 않습니다.
