# Spec Delivery

Inspect the exact current artifact after the final write to the specification. If it is unreadable or its current state is unverified, report that boundary and do not claim completed delivery.

Prepare this decision digest in the current user's language:

1. One outcome sentence naming what the specification now defines and linking the exact current artifact inspected after the final write.
2. Up to three one-line items for the chosen direction, material deltas, or implementation-significant constraints.
3. When applicable, one boundary sentence for unresolved, unverified, partial, or not-started work.

If a project report format exists, place those same items in its existing outcome, change, or review fields; do not add a parallel block.

The linked specification is authoritative. The digest locates and explains it; it does not add, remove, or alter requirements. Summarize decisions, not document sections, prose, tables, checks, or unchanged context.

State partial or unverified work instead of completion. Honor a user-supplied format or length. Do not append a generic review, approval, or transition prompt. If the current user/project contract explicitly requires a gate, place it only in the existing required field with no parallel block. This skill adds no approval, PM, planning, implementation, commit, or transition workflow.
