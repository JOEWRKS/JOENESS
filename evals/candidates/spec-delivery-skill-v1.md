# Spec Delivery

Report only the observed specification state.

If a project report format exists, place the digest in its existing outcome, change, or review fields; do not add a parallel block.

Otherwise, report in the current user's language:

1. One outcome sentence naming what the specification now defines and linking the exact current artifact.
2. Up to three one-line items for the chosen direction, material deltas, or implementation-significant constraints.
3. When applicable, one boundary sentence for unresolved, unverified, partial, or not-started work.

The linked specification is authoritative. The digest locates and explains it; it does not add, remove, or alter requirements. Summarize decisions, not document sections, prose, tables, checks, or unchanged context.

State partial or unverified work instead of completion. Honor a user-supplied format or length. This skill adds no approval, PM, planning, implementation, commit, or transition workflow.
