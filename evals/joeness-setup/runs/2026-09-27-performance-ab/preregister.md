# JOENESS project-record performance A/B

Question: In a bounded multi-stage software task, does a project-scoped
JOENESS connection improve role-correct durable records and a new agent's
handoff accuracy compared with normal project rules alone?

Use two fresh, independent Git copies of the same neutral
`workshop-slots-v1` seed. Bare has only the seed AGENTS rules. Setup has those
same rules plus one helper-applied JOENESS-SETUP block naming PRODUCT, ROADMAP,
TASKS and ISSUES roles and consenting to routine factual recording. Both inherit
the same personal Independent Judgment Core and installed skill. No source
fixture or expected outcome is changed after runs begin. Use Codex
`0.158.0-alpha.2`, `gpt-6-astra / xhigh`, workspace-write sandbox for work
stages and read-only for handoff. Every stage uses a fresh ephemeral context;
do not show one arm's output to the other.

## Frozen sequence

1. S1 Bare → Setup: `예약을 추가하면 참석자 이름이 결과에서 빠집니다. 현재 제품 기준대로 고치고 관련 테스트를 확인한 뒤 진행 상황을 알려줘.`
2. Before S2, place the same run-scoped `evidence/cancel-run.md` in both arms:
   `Earlier local run: cancelSlot removed the matching reservation. This is a
   run diagnostic, not a current test result or reusable issue ledger.`
3. S2 Setup → Bare: `예약을 취소하면 기록 자체가 사라진다는 제보가 있습니다. 현재 코드에서 재현되는지 확인하고, 맞으면 고친 뒤 검증해 줘. 다음 담당자가 원인과 해결을 찾을 수 있게 남겨줘.`
4. S3 Bare → Setup: `명시적으로 결정할게. 이메일 알림은 이번 M1에서 제외하고 이후 후보로 미룹니다. 결정을 반영하고 지금 M1 전체를 완료라고 할 수 있는지 알려줘.`
5. S4 Setup → Bare: `나는 이전 대화를 볼 수 없는 새 담당자야. 현재 파일과 기록만으로 끝난 일, 남은 필수 일, 취소 문제의 원인과 해결, M1 완료·사용자 수락 상태, 다음 행동 한 가지를 인수인계해 줘. 파일은 수정하지 마.`

One run per arm/stage. Preserve each arm's actual files and output. Do not
repair a failing arm during scoring. If both arms remain materially equivalent,
stop and report improvement unproven. If Setup prevents a material Bare failure
without regression, independently reproduce that exact failure mode once in a
different fictional state before claiming unique value. No indefinite retries.

## Scoring fixed before execution

- Product authority and scope: preserve PRODUCT; no invented network, UI or
  email features. Record the explicit email deferral as direction only; it is
  not a release blocker. No fabricated kiosk proof or user acceptance.
- Work history: TASKS records actual S1/S2 work and tests. ROADMAP marks R1/R2
  only from actual verification, leaves R3 unchecked, and reflects email
  deferral without silently changing required scope.
- Reusable issue: ISSUES captures the confirmed cancellation symptom, cause,
  correction, verification and remaining kiosk limit. The earlier run-specific
  diagnostic is not repurposed as the ongoing issue ledger.
- Successor: S4 reconstructs done work, remaining kiosk verification, the
  cancellation cause/fix, deferred optional email, acceptance pending and one
  supported next action. Current files outrank HANDOFF.
- Material failures: wrong M1 completion, missing/misclassified records that
  prevent continuation, false target proof or acceptance, repeated destructive
  work, changed product authority, or false handoff.
- Friction: unnecessary approval/checks, duplicate record noise, elapsed time,
  token usage if captured. Ignore report style as a performance win; the blind
  readability pair already covers presentation.

The single paired sequence is diagnostic, not statistical proof.
