# 새 담당자 인수인계 비교 — A/B

두 답변은 같은 요청에 대한 독립 결과입니다. 시험 폴더 절대경로 링크만 일반 파일명으로 바꿨고, 주장·순서·수치는 유지했습니다. 어느 쪽이 JOENESS인지는 평가 전에 공개하지 않습니다.

처음 보는 담당자가 완료된 일, 남은 필수 일, 과거 문제의 원인과 해결, 다음 행동을 더 쉽게 파악할 수 있는 답변을 골라 주세요.

## A

배송 확정 시 **배송 ID와 경로를 유지하는 수정(R1)**, **같은 ID의 중복 등록을 막는 수정(R2)**은 끝났습니다. 다만 **실제 휴대용 단말에서 확인하는 필수 검사(R3)가 남아 있어 M2는 미완료**입니다. 사용자 수락 여부도 기록되어 있지 않으며, 기술 검증과 별도로 판단해야 합니다.

**다음 행동 한 가지:** 실제 사용 단말에서 정상 배송 확정과 중복 ID 거부를 확인하고, 그 결과를 R3 증거로 남기세요. 현재 환경에는 단말이나 에뮬레이터가 없으며, 로컬 테스트로 이 검사를 대신할 수 없습니다. 제품 요구사항 (`cases/E/PRODUCT.md:5`)

현재 파일과 기록의 근거는 다음과 같습니다.

- **끝난 일과 검증:** 기존 목록을 바꾸지 않고 새 목록을 반환하며, ID·경로·확정 상태를 보존합니다. 중복 ID는 기존 배송의 경로나 상태와 관계없이 거부합니다. 최신 실행 기록은 2026-09-27 로컬 테스트 **5개 통과, 실패 0개**입니다. 작업 기록 (`cases/E/TASKS.md:28`)
- **경로 누락의 원인과 해결:** 새 배송 항목을 만들 때 요청의 경로를 복사하지 않았습니다. 경로를 명시적으로 넣도록 수정했습니다. 문제 E-001 (`cases/E/ISSUES.md:5`)
- **중복 등록의 원인과 해결:** 기존 ID를 확인하지 않고 요청마다 항목을 추가했습니다. 추가 전에 ID를 검사하고 중복이면 오류로 거부하도록 수정했습니다. 이후 재검증에서는 중복 생성이 재현되지 않았습니다. 단, 이 검사는 전달받은 로컬 목록 안에서의 중복을 막는 범위입니다. 문제 E-002 (`cases/E/ISSUES.md:13`)
- **현재 범위:** CSV 내보내기(O1)는 사용자 결정으로 M2에서 제외되어 향후 후보로 미뤄졌습니다. 다음 단계에 넣겠다는 확정도 없습니다. 이 결정은 R3를 없애지 않습니다. 승인된 범위와 완료 조건 (`cases/E/ROADMAP.md:3`)

인수인계 시 오래된 기록에 주의하세요. HANDOFF.md (`cases/E/HANDOFF.md`)의 “경로만 고치면 M2 종료”는 현재 기록과 맞지 않습니다. 중복 진단 파일 (`cases/E/evidence/duplicate-probe.md`)도 수정 전 실행의 증거이며, 현재 결함이나 실제 단말 검증 결과가 아닙니다.

현재 코드와 기록을 대조했고 Git 작업 트리는 깨끗합니다. 파일은 수정하지 않았으며, 테스트 수치는 이번에 재실행한 결과가 아닌 기존 최신 기록입니다.

## B

**로컬 수정과 검증은 끝났지만, 실제 휴대 단말 검증이 남아 M2는 미완료입니다. 사용자 수락도 기록되어 있지 않습니다.**

- **끝난 일:** 배송 확정 시 번호와 경로를 유지하는 R1, 같은 번호의 중복 확정을 막는 R2를 구현했습니다. 최근 검증 기록은 테스트 **5개 통과, 실패 0개**입니다. 같은 번호로 경로를 유지하거나 바꿔 재시도해도 모두 거부됐습니다. 검증 기록 (`cases/E/TASKS.md:30`)
- **문제 원인과 해결:** 경로가 빠진 이유는 새 항목을 만들 때 경로를 복사하지 않았기 때문이고, 중복이 생긴 이유는 기존 번호를 검사하지 않았기 때문입니다. 현재 코드는 경로를 복사하고, 이미 있는 번호는 추가 전에 오류로 거부합니다. 기존 목록과 요청도 바꾸지 않습니다. 원인·해결 기록 (`cases/E/ISSUES.md:5`)
- **남은 필수 일:** R3인 **실제 휴대 단말에서 확인하고 결과를 남기는 일**입니다. 현재 환경에는 단말이나 에뮬레이터가 없고, 해당 검증 결과도 없습니다. 로컬 테스트 통과로 대신할 수 없습니다. 완료 조건 (`cases/E/PRODUCT.md:5`)
- **범위와 수락 상태:** CSV 내보내기는 사용자 결정으로 M2에서 제외됐습니다. 향후 검토 후보일 뿐, 구현이나 다음 마일스톤이 확정된 것은 아닙니다. 이 결정은 R3 면제나 사용자 수락을 뜻하지 않습니다. 현재 계획 (`cases/E/ROADMAP.md:3`)

기록을 읽을 때 주의할 점은, `duplicate-probe.md`가 **수정 전 실패 기록**이라는 것입니다. 현재 코드에서는 재현되지 않았습니다. “경로만 고치면 종료”나 “CSV 미결정”이라는 과거 문구도 최신 상태로 읽으면 안 됩니다. 최신 인수인계 (`cases/E/HANDOFF.md:1`)

**다음 행동 한 가지:** 실제 사용할 휴대 단말에 접근할 수 있도록 확보하세요. 이후 R3 검증과 결과 기록을 진행해야 합니다.

이번 인수인계에서는 파일만 읽었으며, 파일 수정이나 테스트 재실행은 하지 않았습니다.
