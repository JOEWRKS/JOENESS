- 자료: 제품 맥락 README.md, 방향 ROADMAP.md, 작업 TASK.md. 이슈·디자인 전용 문서는 미사용.
- 새 작업·재개 전 ROADMAP의 현재 단계 또는 방향 대기, 진입 조건, 필수 확인, 다음 작업을 찾고 요청에 필요한 자료만 읽는다.
- 현재 파일과 Git 상태로 진행을 확인한다. 미충족 조건은 종속 작업만 막으며, 별도로 승인된 독립 작업은 진행할 수 있다. 범위·순서 변경은 명시적 결정이 필요하다.
- 실제 작업의 중요한 사실과 확인 결과는 TASK에 기록한다. 반복 가능한 이슈의 별도 기록처가 필요해지면 제안한다. 중복 설명 대신 원문 항목을 연결한다.
- 질문·의견·설명만 한 대화와 기록 제외 요청은 기록하지 않는다. 기록 제외는 별도로 승인된 구현을 취소하지 않는다. 완료 작업에 달라진 사실이 없으면 기록을 추가하지 않는다.
- 실질 작업 보고는 작업, 업데이트 파일, 이슈, 해결, 남은 문제, 다음 작업의 여섯 짧은 하이픈 항목으로 시작한다. 빈 항목은 없음. 해결은 확인된 수정이며 단순 검사 통과가 아니다.
- 방향·범위는 명시적 결정으로만 바꾸고 필수 항목의 확인·증거 상태는 실제 검증으로 갱신한다. 상태 변경 시 ROADMAP의 현재/다음도 함께 갱신한다.
- 작업 완료가 단계·출시 완료는 아니다. 완료 선언 전 모든 필수 항목·검증·필요한 사용자 수용을 확인한다. 미착수·진행·검증 대기·보류는 열린 상태이며 범위 제외는 승인된 이유와 기록을 남긴다.
- 목표가 미정이면 단계를 만들지 않는다. 승인된 단계가 생기면 목표·진입 조건·필수 결과·각 확인과 증거 공백·완료 조건·다음을 ROADMAP에 둔다.
