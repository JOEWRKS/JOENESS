# 프로젝트 작업 연결

- 목적은 `README.md`, 현재 작업·검증·다음 행동은 `TASK.md`를 기준으로 한다. 관련 역할만 읽는다. 별도 이슈·디자인 문서 역할은 사용하지 않는다.
- 로드맵은 사용자 요청으로 제외했다. 새 작업·재개 시 `TASK.md`와 필요한 목적 자료를 읽고 현재 파일/Git 상태로 확인한다. 승인되지 않은 목표·단계·순서를 만들지 않는다. 이후 승인된 순서 있는 목표가 생기면 로드맵 역할을 제안한다.
- 일상 기록 동의: 승인된 작업의 의미 있는 변경·검증·남은 문제·다음 행동을 `TASK.md`에 짧게 기록한다. 사실은 한 곳에 두고 다른 곳에는 해당 항목을 연결한다. 반복되는 이슈 기록의 별도 출처가 필요해지면 제안한다.
- 질문·의견·설명만 하는 요청과 기록 제외 요청에는 기록하지 않는다. 기록 제외는 별도로 승인된 구현을 취소하지 않는다. 이미 완료된 작업에 바뀐 사실이 없으면 상태만 알리고 반복 기록하지 않는다.
- 실질 작업과 사람에게 넘기는 인계는 여섯 하이픈 항목으로 시작한다: 작업, 업데이트 파일, 이슈, 해결, 남은 문제, 다음 작업. 각 항목은 일상 표현의 짧은 사실 하나이며 빈 항목은 없음이다. 업데이트 파일은 이번에 바뀐 파일의 목적만, 이슈는 문제, 해결은 검증된 수정만 적는다. 통과한 확인은 해결이 아니다. 남은 문제에는 미확인 작업을 포함하며 다음 작업은 승인 범위에서 정한다. 필요한 경로·증거·승인 경계만 뒤에 덧붙인다. 단순 질문에는 이 보고 형식이 필요 없다.
- 작업 완료를 단계·릴리스 완료나 사용자 수락으로 확대하지 않는다. 제안과 승인, 검증 사실과 사용자 수락을 구분한다. 의존 조건이나 승인 범위를 바꾸는 요청은 충돌을 설명하고 명시적 결정을 구하되 독립적으로 승인된 작업은 진행한다.
- 출처 접근이나 기록 쓰기가 실패하면 정확한 경계를 알리고 가능한 독립 작업은 진행한다. 저장하지 못한 기록을 저장했다고 말하지 않는다.
