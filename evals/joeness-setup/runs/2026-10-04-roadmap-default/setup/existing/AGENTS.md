# JOENESS 프로젝트 연결
- 제품 결정은 PRODUCT.md, 방향·현재 단계·작업 이력은 WORK.md, 필수 결과 상태·검사 근거는 CHECKS.md가 원본이다. 별도 문제·디자인 문서는 사용하지 않는다.
- 요청에 필요한 역할만 읽는다. 새 작업·재개는 WORK.md의 Current와 해당 단계, 연결된 CHECKS.md 항목에서 진입 조건·필수 검사·다음 가능한 작업을 확인한다.
- 현재 파일·Git·실제 대상과 기록을 비교한다. 과거 기록은 현재 검증의 대체물이 아니다. 완료한 일을 반복하지 않으며 변경된 사실이 없으면 반복 기록하지 않는다.
- 미충족 진입 조건은 의존 작업을 막는다. 독립적으로 승인된 일은 진행할 수 있다. 순서·범위·의존 관계를 바꾸려면 명시적인 방향 결정이 필요하다.
- 승인된 일상 기록: 실제 작업·진행·남은 일은 WORK.md의 History에, 필수 결과 상태와 실제 검사 근거는 CHECKS.md의 해당 항목에 한 번 기록하고 정확한 항목을 연결한다. 재사용할 문제 기록의 별도 필요가 생기면 저장 위치를 제안한다.
- 질문·의견·설명과 기록 제외 요청은 기록하지 않는다. 기록 제외는 별도로 승인된 구현을 취소하지 않는다. 기록 중지는 연결 안내를 유지하며 변경한다.
- 필수 항목은 실제 검증으로만 갱신한다. 상태가 바뀌면 WORK.md의 Current와 다음 작업도 남은 항목에서 함께 맞춘다. 제품 결정과 사용자 수락을 검사 결과로 대신하지 않는다.
- 단계·마일스톤·릴리스 완료 전 모든 필수 항목의 상태·근거·필요한 사용자 수락을 확인한다. 미착수·진행 중·검증 대기·보류는 열려 있다. 범위 제외는 승인과 이유를 남기며 항목을 삭제하지 않는다. 작업 완료와 단계 완료를 구분한다.
- 실질 작업과 인수인계 후 작업, 업데이트 파일, 이슈, 해결, 남은 문제, 다음 작업의 여섯 하이픈 항목으로 보고한다. 짧은 일상어로 쓰고 빈 항목은 없음으로 적는다. 업데이트 파일은 이번 변경만 목적별로, 해결은 검증된 수정만, 남은 문제는 미해결·미검증, 다음 작업은 승인 범위와 로드맵에서 가져온다. 필요한 경로·근거·수락 경계만 뒤에 적고 단순 질문에는 보고 틀을 강제하지 않는다.
- 원본 접근이나 기록 저장에 실패하면 정확한 경계를 보고하고 독립 작업은 계속한다. 기존 문서 역할·이력과 사용자 소유 내용을 보존한다.
