기준: PRODUCT.md. 진행과 순서: ROADMAP.md. 작업과 검증: TASK.md. 이슈·디자인 전용 문서는 현재 사용하지 않는다.
새 작업·재개 전에 로드맵의 현재 단계, 진입 조건, 필수 결과와 다음 작업을 확인한다. 요청에 관련된 역할만 읽는다.
현재 파일과 Git 상태로 확인하고, 미충족 선행 조건에 의존하는 후속 작업은 진행하지 않는다. 독립적으로 승인된 작업은 진행할 수 있다. 완료된 작업을 반복하지 않는다.
승인된 일상 작업의 사실·검증·남은 일을 TASK.md에 기록한다. 질문·설명·의견·기록 금지 요청은 기록하지 않는다. 다른 역할에서 같은 사실이 필요하면 원문 항목을 연결한다. 반복되는 이슈 기록의 필요가 생기면 적합한 기록 위치를 제안한다.
로드맵의 검증 상태는 실제 증거로 갱신하고 현재 단계와 다음 작업도 함께 맞춘다. 완료된 항목을 다음 작업으로 남겨두지 않는다.
범위·순서는 명시적 결정으로만 바꾸며, 단계 완료 전 모든 필수 결과와 증거를 확인한다. 보류와 검증 대기는 미완료다. 작업 완료는 단계·릴리스 완료가 아니며 기술적 완료와 사용자 수락은 구분한다. 제품 기준을 보존한다.
실질 작업과 사람에게 인계하는 보고는 작업 / 업데이트 파일 / 이슈 / 해결 / 남은 문제 / 다음 작업의 여섯 하이픈 줄로 시작한다. 각 줄은 짧은 사실 하나이고, 변경 파일은 목적 이름으로 표현하며 빈 항목은 없음으로 쓴다. 다음 작업은 승인 범위나 로드맵에서 가져온다. 단순 질문에는 이 보고를 붙이지 않는다.
해결은 검증된 문제 수정이며, 통과한 점검 자체를 해결로 쓰지 않는다. 남은 문제에는 미해결·미검증 사항을 적고, 필요한 정확한 경로와 증거·수락 한계는 상세 보고에 둔다. 접근·기록 실패는 실제 경계를 알리며 저장했다고 주장하지 않는다.
