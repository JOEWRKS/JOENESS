# 로드맵 기본 연결 보강 — 로컬 검증

판정: **구현·로컬 작동 검증 완료. 배포 미완료.**

후보 `0.3.1-dev`, 기준 커밋 `7ff231df7b9aa449ca587b2c1847341c71ed58a9`. 이번 결과는 그 위의 미커밋 변경에 해당한다. 정확한 시험 명령·출력·문서 해시는 [observed.json](observed.json), 스킬 파일별 해시는 저장소의 `vendor/source-manifest.json`에 있다.

## 발견한 문제와 보강

- 문구만 맞추는 검사로는 실제 로드맵 생성·재사용·후속 단계 판단을 증명하지 못함 → 중립 Git 프로젝트에 실제 적용하고 산출 문서를 검토.
- 연결 도구의 `current`가 로드맵 내용까지 검증했다는 오해 가능 → 결과에 `verificationScope: managed-connection-only` 추가. 설정 완료 전 실제 AGENTS·로드맵의 경로, 정본, 단계 조건, 현재/다음 작업을 다시 읽도록 보강.
- 변경된 스킬을 기존 출시본과 같은 버전으로 식별 → 소스 후보를 `0.3.1-dev`로 분리. 설치기·manifest·테스트·안내 일치.
- 로드맵 역할을 기본 포함하되 기존 정본 재사용, 명시적 제외, 목표 미정 경계 유지. 사용자 승인 없는 목표·단계·검증 결과 생성 금지.

연결 도구는 여전히 AGENTS 관리 구역과 상태 파일만 소유한다. 로드맵을 자동 판정하는 새 엔진이나 전역 규칙은 추가하지 않았다.

## 실제 행동 시험 — 5건 통과

아래 요청은 시험 목적을 요약한 것이며 원본 프롬프트의 축어 전사가 아니다. 모델/노력 설정은 GPT-6 Astra / xhigh, 각 담당자는 새 문맥으로 시작했다.

| 사례 / 담당자 | 입력·승인 범위 | 확인한 실제 결과 |
| --- | --- | --- |
| 신규 / roadmap_new_case | 독서 목록: 책 추가·제목 검색 후 내보내기. 설정 문서 생성과 기록 승인. 기술·형식 미정. | [ROADMAP](setup/new/ROADMAP.md) 생성. 추가·검색 검사를 분리하고 실제 앱 검증 전 내보내기 차단. PRODUCT 원본 보존. |
| 기존 / roadmap_existing_case | WORK=방향·이력, CHECKS=검증, PRODUCT=제품. 등록 후 내보내기. 과거 구현·단위 검사는 완료지만 태블릿 검사 없음. 도움말 수정은 별도 승인. | [WORK](setup/existing/WORK.md) 재사용, ROADMAP 중복 생성 없음. 잘못된 다음 작업 수정. 태블릿 검사 미완 유지, 독립 도움말 작업 허용, W1 원문 보존. |
| 목표 미정 / roadmap_unknown_case | 목표·기술·기한 없는 빈 프로젝트 연결 승인. | [ROADMAP](setup/unknown/ROADMAP.md)에 방향 미정과 필요한 결정만 기록. 제품·단계·일정 창작 없음. |
| 명시적 제외 / roadmap_optout_case | 일회성 기록용 프로젝트. 사용자가 로드맵 제외, 최소 작업 기록 승인. | [AGENTS](setup/optout/AGENTS.md)에 제외·기존 기록 경로·나중에 순서 있는 목표가 생길 때 제안할 조건 기록. ROADMAP 생성 없음. |
| 새 담당자 재개 / roadmap_resume_case | 기존 사례의 연결된 문서만 제공. 태블릿 검사는 여전히 불가. 내보내기 다음 사용 안내 단계 추가 승인. | [WORK](resume/existing/WORK.md)와 [CHECKS](resume/existing/CHECKS.md)에 새 단계·검사를 연결. 등록 → 내보내기 → 사용 안내 순서 보존. 미검증을 완료로 바꾸지 않고 독립 작업 구분. |

신규·기존·미정·제외 사례에서 Apply 및 Check는 연결 상태 current를 반환했다. 이를 내용 검증으로 대신하지 않고 실제 산출 파일을 별도로 읽었다. 재개 담당자에게 JOENESS 스킬을 다시 제공하지 않고 프로젝트 연결 문서로만 작업하게 했다.

기존 사례의 setup 스냅샷은 후속 변경 전 상태, resume 스냅샷은 후속 변경 후 상태다. 24개 스냅샷은 시험 파일의 SHA-256과 대조했다. 실서비스·게임 구현·기기 시험을 수행했다는 뜻이 아니다.

## 한계와 다음 작업

자동 앱 지침 전달, 새 후보의 개인 설치, 원격 CI, 최종 커밋·출시는 아직 확인하지 않았다. 새 문맥 시험은 명시적인 파일 읽기로 평가했으므로 자동 전달 성공으로 확대하지 않는다. 토큰 절감·속도·일반적 정확도 향상도 측정하지 않았다.

필요한 보강은 실제 파일 확인과 연결 범위 구분이며, 모든 문서를 강제로 생성하거나 상태를 자동 감독하는 기능은 아니다. 다음은 검증된 후보의 검토·출시 범위 결정이다. 이전 실패·기존 출시 기록은 삭제하지 않았다.
