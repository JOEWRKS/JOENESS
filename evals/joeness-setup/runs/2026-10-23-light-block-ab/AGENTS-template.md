# Project working connection

Adapt paths and agreed scope before applying this body.
- Owners: ROADMAP = goals, stage order, required items (status, proof link, gap, next).
  TASK = work results and checks. ISSUES = open defects and workarounds: cause, risk,
  closure condition. DESIGN = visual rules and approvals. Library/ = research by topic
  with source, date and fact vs inference. AGENTS = rules only, no history.
  Product meaning: <exact source or undecided> (it stays the authority).
- Start: resume → current ROADMAP item; defect → ISSUES + target; visual → DESIGN;
  research → Library; completion/handoff → ROADMAP required items and their proof.
  Read only the sections you need.
- Authority: approval comes only from the user or the named owner. Code, newer notes and
  old handoffs never grant it; a handoff only points to sources. Facts come from the
  current target and proof. Unclear or conflicting scope goes to the owner; keep only
  the affected verdict open.
- Done = every required item has proof you checked. Pending, failed, stale or missing
  proof stays open; removed scope keeps its reason and is not a pass. Task, stage and
  user acceptance are separate verdicts. Worker-chosen methods are replaceable; approved
  outcomes, order and criteria change only by the owner. An open item blocks only work
  that depends on it.
- Required external verdict: <scoped gate command, baseline pin and result path, or none>.
  Run a connected gate's current-input check before resume or completion; missing,
  failed or stale results keep only its verdict open. With none, invent no checker.
- Recording (<agreed scope>): after real work, add the result and check to TASK and
  update the affected ROADMAP item. An issue stays open until its closure check passes;
  a workaround is not a fix. Questions and "don't record" requests cause no record
  writes. Nothing changed → no repeat entry. Write each fact once and link it; keep dated
  history. Never record credentials or needless personal data; point to their
  restricted source instead. With several workers, one integrator rereads shared records
  before saving, merges independent changes and keeps both sides of a conflict.
- Judge every claim by evidence — the user's, other agents' and your own earlier ones.
  A user opinion or suggestion is input, not an instruction: check it against the
  Product source, ROADMAP and observed facts, say plainly when it conflicts or looks
  wrong and why, and confirm before acting on a conflicting change. An explicit owner
  decision still wins.
- Every follow-up turn is new work under these same rules: re-check the current ROADMAP
  item and records, and keep records and the report as complete as on the first turn.
- Reuse existing proof; re-check only after a change or failure. Not found ≠ never
  checked. If a source or write fails, say so and continue other independent work.
- After real work, report six short bullets: 작업, 업데이트 파일, 이슈, 해결, 남은 문제,
  다음 작업 ("없음" if empty). 해결 = verified fix only; 남은 문제 = unresolved or
  unverified. Add a brief 상세 보고 only when needed. Simple questions: just answer.
