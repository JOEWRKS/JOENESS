## JOENESS project connection

AGENTS owns concise work rules, owner locations and read/update triggers, not history or progress. Use the following canonical owners; read only sections relevant to the task.

| Owner | Path and responsibility |
| --- | --- |
| ROADMAP | [ROADMAP.md](ROADMAP.md): project goals/scope, ordered stages, required outcomes/checks, current states, gaps and next work. No common rules, role tables or detailed research. |
| TASK | [TASK.md](TASK.md): performed work, changes, checks/results/limits and proof linked to roadmap items; one-off reviews belong here. No competing current-stage ledger. |
| ISSUES | [ISSUES.md](ISSUES.md): unresolved defects, causes, effective workarounds, residual risks, closure conditions/proof; not every unfinished feature. |
| DESIGN | [DESIGN.md](DESIGN.md): approved visual authority/version/scope versus proposed changes; not product approval or progress. |
| Library | [Research](Library/geo-commerce-research.md) and [reusable evaluation method](Library/geo-commerce-evaluation-method.md): topic-based knowledge, sources, checked dates, observations versus inference, scope/uncertainty; not decisions or current progress. |

Product meaning and material unresolved decisions belong to [GEO state](product-definition/geo-fresh-market/state.json). Existing dogfood state and docs/superpowers plans retain their separate scope and history; do not turn the post-M6 plan into a commerce prerequisite or overwrite tooling with the example site.

Before new/resumed substantive work, read ROADMAP's relevant item and entry conditions, then related TASK proof, ISSUES and actual target as needed. Research follows the question to relevant Library/source sections; visual work also reads DESIGN authority. Check existing proof before declaring it missing; failed lookup is not evidence of absence. Reuse valid proof and repeat only checks affected by change, failure or an uncovered condition.

Routine factual recording is enabled for authorized substantive work: execution/checks go to TASK; research detail to the existing Library topic; defects/workarounds/closure to ISSUES; affected status/gaps/next work to ROADMAP. DESIGN and product decisions change only with authorized direction. Questions, opinions and no-record requests create no records. Recording may be disabled while retaining navigation; no background worker is activated.

Never copy credentials or unnecessary personal data into records, reports or Git. Keep the needed meaning in a redacted summary and an authorized restricted source locator that exposes no secret; unclear access/storage scope means leave raw material at source and report the access gap.

For parallel shared records, the current GEO primary agent is the integrator for affected TASK/ROADMAP/ISSUES entries; other workers provide scoped results and proof. Before saving, reread current entries against the working baseline, merge independent changes, and preserve conflicting intent/approval sources with only the affected verdict open. Reconcile a changed baseline before retrying. This is not an atomic lock.

Write each detailed fact once and link it. Reuse a topic/section before creating a file; split only for independent retrieval/reuse/update needs or demonstrated navigation burden, not each date or task. Keep source, cause, uncertainty and approval boundaries. Preserve dated evidence and distinct past decisions; correct conflicting current summaries at their owner. Do not use private backups as authority to discard unique live history.

Unmet entry conditions block dependent work only; independent authorized work may proceed. Changing approved goals, scope, order or completion criteria requires explicit authorized user direction. Before stage completion, verify every required item and actual evidence. Pending, on-hold and unverified work remain open; scope removal retains an authorized reason and never counts as passed. Task completion, stage completion, technical verification, user acceptance and external AI-search outcomes are distinct.

Inspect actual targets and proof, not field presence alone. Seller claims and candidate benchmarks do not establish certification, live stock, reuse permission or GEO performance. Preserve unknowns; do not infer food safety from nationality/GMO labels, guarantee AI indexing/citation, or fabricate approval, policy or results. Users decide direction/material policy/acceptance; the primary agent coordinates and evaluates within that scope; subagents work only when authorized.

After substantive work/handoff, start the response with six short Korean bullets in everyday words: 작업, 업데이트 파일, 이슈, 해결, 남은 문제, 다음 작업. 해결 means a verified fix, not a passing check. Use 없음 when empty; list actual changed files and derive next work from authorized scope/ROADMAP. Put necessary details after the six bullets, briefly and without repeating them. Ordinary questions need no work report. Keep connection integrity, document suitability, actual task verification and fresh-context delivery separate.
