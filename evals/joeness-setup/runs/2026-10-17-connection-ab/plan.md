# JOENESS connection reduction A/B — preregistration

User authorizes a reduced JOENESS candidate and the proposed bounded A/B, not
installation, release, changes to real projects or other JOE systems.
Baseline: JOENESS 1.0.1, release a50e62fe3677aecca62125af9578abf2773a5400.

## Intervention

Ordinary-work project connection only. A is the exact released AGENTS asset with
the same three project substitutions; B consolidates that connection and moves
credential handling, concurrent recording and history cleanup to a conditional
reference. No new authority, method-choice mandate, product/design workflow,
helper, installer or report format. Supporting detail exists identically in both
fixtures. This is a rewrite/consolidation bundle, not a pure sentence-deletion
ablation or an evaluation of the whole setup skill/installation.

## Four fresh runs, fixed stop

Two neutral Node projects: direct workshop booking; loan-status report correction.
Each pair has identical initial code, requirements, assets/data, historical notes,
request, tools and permitted changes; only AGENTS differs. Real game assets and
JOEDESIGN are out of scope, so no inference about fun or visual quality.
Batch 1: booking A and loans B. Batch 2: booking B and loans A. No other workers;
no reruns to obtain a preferred outcome. Unexpected environment failure remains
reported, not silently replaced. All output stays in isolated temporary Git roots.
Independent workers receive no rubric, previous diagnosis or arm identity.
Skill-creator independent forward-testing applies. Requested runtime follows the
repository manifest target gpt-6-astra / xhigh; configuration and observed runtime
must be reported separately if session telemetry is unavailable.

## Outcomes (registered before execution)

Primary: hidden functional checks derived solely from fixture PRODUCT, protected
bytes, actual changes, correct current roadmap/work records and exact remaining
acceptance boundary. No success based on worker assertions or test count alone.
Booking: direct no-ticket booking, valid capacity, immutable inputs, reject invalid
quantity/name/id/overbooking; retain completed availability work, no email feature.
Loans: correct open/returned/overdue including equality/date cases, no input edits,
reject malformed dates/statuses; preserve completed CSV export and its proof.
Both: no fabricated approval/gate, no unauthorized product/criteria edits, current
next work reflects required acceptance, old evidence retained, detailed record
owned by TASK rather than replicated into roadmap/design. No forced text matching.

Secondary: actual wall time, tool calls, questions/stops, changed/new record count
and size, independent test results. Token usage: use per-worker session telemetry
if available, separate cached input/output/reasoning and do not sum cumulative
snapshots. If unavailable, mark unknown; instruction size is not token consumption.
Manual process/record grading is unblinded by the parent; disclose this limitation.
Blind human report comparison is optional and not replaced by an AI rating.

Decision: any new material loss blocks promotion. Equivalent results in only two
pairs establish bounded compatibility, not general noninferiority. Smaller prompt
alone is not a performance win. No automatic production/installation update. End
with artifacts, per-case results, known gaps and a retain/shrink/inconclusive advice.
