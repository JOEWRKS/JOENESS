# JOENESS 연결문 축소 A/B — 결과

판정: **일반 코드 작업 두 건에서는 축소 가능성 확인. 제품 전면 교체·설치 승격은 보류.**
사전 등록한 새 작업 4회로 종료했으며, 결과를 개선하려는 재실행·후보 수정은 하지 않았다.
현재 제품/개인 설치와 실제 프로젝트는 변경하지 않았다.

## 비교 범위

- 기준 제품: JOENESS 1.0.1, `a50e62fe3677aecca62125af9578abf2773a5400`.
- A: 배포된 프로젝트 연결문에 프로젝트 경로·기록 동의·외부 필수 검사 없음만 지정.
- B: 역할/완료/기록/보고 원칙의 중복 표현을 통합. 자격증명·공동 기록·이력 정리 상세는 해당 작업 때 읽는 자료로 분리.
- 두 과제: 공방 직접 예약 구현, 반납 항목의 연체 오집계 수정. 각각 A/B 1회.
- 쌍별 초기 파일은 AGENTS 외 해시 동일. 상세 참고 파일도 양쪽에 동일하게 존재.
- 실제 세션 네 개 모두 `gpt-6-astra`, `xhigh` 확인. 단순 요청 설정만으로 추정하지 않음.
- `skill-creator`의 독립 실행 방식을 사용. 작업자는 평가표·기대 구현·이전 진단을 받지 않았음.
- 설치 스킬 전체, 검사 도구, JOEDESIGN, 게임 아트/재미의 비교가 아님.

기능검사는 사전에 작성해 숨긴 8개 묶음/과제이며, 개별 assertion 8개라는 의미는 아니다.
작업자가 작성한 검사 개수는 구성이 달라 품질 점수로 비교하지 않는다.
보호 파일 수는 독립 평가자가 package.json까지 포함한 수치라 작업자 보고와 다를 수 있다.
명령 수는 세션의 CommandExecution 항목 수다. 한 명령에 여러 검사가 포함될 수 있어
도구 호출 전체나 검사 횟수와 같지 않다. 파일 수정은 FileChange 항목 수다.

### 실제 코드·기록 검토

- 네 실행 모두 요청한 기능/결함을 해결하고 사전 오류 조건·원본 보존 검사를 통과.
- 확인표 요구 제거, 완료된 잔여 조회/CSV 보존, 범위 밖 메일·배포 추가 없음.
- 현재 ROADMAP에 기술 완료와 사용자 수락 대기를 구분. 다음 행동을 사용자 검토로 연결.
- 과거 계획/검사 기록을 현재 승인으로 승격하지 않았고, 기존 문제·검사 이력을 유지.
- TASK에 실행·검사 근거, ISSUES에 원인·해결, ROADMAP에 현재 상태와 다음 작업 기록.
  짧은 상태 중복은 남지만 별도 평가 보고서나 경쟁하는 진행 문서를 만들지 않음.
- 모두 기존 파일 5개만 수정. 새 파일 0, 총 파일 수 예약 12/대여 14로 유지.
- 추가 질문·승인 요구·외부 검사 도구 강제·미완성 상태의 작업 포기 없음.
- 여섯 항목 보고 유지. 사람의 읽기 품질 재평가는 이번에 수행하지 않음.

### 남은 차이 — 통과 결과에 숨기지 않음

1. **예약의 과거 근거 정정:** 기존 TASK는 옛 검사의 입력을 data/sample.json이라고
   썼지만 실제 옛 테스트는 코드 안의 표본이었다. A는 이 불일치를 명시적으로 정정.
   B는 옛 문장을 남기고 새 검사부터 실제 자료를 사용했다. B의 현재 기능/검사 주장에는
   문제가 없으나 과거 근거 정정에서는 A가 더 충실했다. 현재 완료·승인 판단을 바꾸는
   중대 실패로 분류하지 않았지만, 정보 보존/정정이 완전히 동등하다고 주장하지 않는다.
2. **대여의 0000년 처리:** 코드 검토 뒤 양쪽에 같은 추가 입력을 넣었다.
   `summarize([], '0000-01-01')`은 A에서 RangeError, B에서 0건 결과를 반환.
   이 항목은 사전 검사에 없고 PRODUCT에 연도 하한/연도 체계가 명시되지 않았다.
   따라서 사전 8/8 결과를 뒤집는 사후 채점 기준으로 쓰지 않는다. 추가 경계 차이이며,
   모든 날짜 입력에서 동등하다는 주장도 하지 않는다. 이 차이를 고쳐 재실행하지 않았음.

## 사용량

| 과제/판 | 누적 입력 | 그중 캐시 입력 | 비캐시 입력 | 출력 | 기록된 총 토큰 |
|---|---:|---:|---:|---:|---:|
| 예약 A | 529,364 | 500,224 | 29,140 | 7,045 | 536,409 |
| 예약 B | 381,790 | 369,152 | 12,638 | 5,996 | 387,786 |
| 대여 A | 469,559 | 446,848 | 22,711 | 8,356 | 477,915 |
| 대여 B | 421,761 | 400,128 | 21,633 | 7,351 | 429,112 |
| 현행 합계 | 998,923 | 947,072 | 51,851 | 15,401 | 1,014,324 |
| 축소 합계 | 803,551 | 769,280 | 34,271 | 13,347 | 816,898 |

- 연결문: 4,836→2,399 UTF-8바이트, **50.4% 감소**. 문자 수는 4,752→2,351.
- 이번 두 작업 합산: 총 토큰 **19.5% 감소**, 출력 **13.3% 감소**,
  비캐시 입력 **33.9% 감소**, 작업 시간 **16.2% 감소**.
- 작업 명령 26→21, 파일 수정 호출 7→5. 세 기록 문서 합계 9,419→9,031바이트
  (약 4.1% 감소): 지침이 절반이 됐다고 산출 문서도 절반이 된 것은 아님.
- 총 토큰은 여러 모델 호출의 입력을 누적한 값이며 대부분은 캐시 입력이다.
  한 번에 읽힌 지침 길이도, 청구 비용도 아니다. 캐시/추론 토큰을 중복 합산하지 않았다.
- 각 작업 첫 task_complete 직전의 최종 누적 snapshot만 사용. 중간 snapshot을 합산하지 않음.
  추론 출력은 출력의 일부. 부모 평가 작업 및 종료 후 원문 보존용 두 응답은 비교 사용량에서 제외.

### 원인 판단

이번 실행에서는 축소판의 명령/수정 호출과 출력이 적어 재입력 누적도 줄었다.
현행 예약은 보호 해시 출력 형식을 다시 수집하고 문서 수정 전후를 읽었으며,
현행 대여는 차이/기록/형식 검사를 더 많은 명령으로 나눴다.
축소 대여도 .git까지 포함한 넓은 해시 수집을 두 번 수행했다. 불필요한 읽기가
완전히 없어진 것은 아니다. 검사 실패→수정→성공의 정상 회귀 검사를 낭비로 분류하지 않는다.

이 차이가 모두 연결문 축소 때문에 발생했다고 단정할 수 없다. 각 조건 1회뿐이며
모델 변동, 명령 묶음 선택, 캐시 적중률과 공통 호스트 지침의 영향이 함께 있다.
입력 감소를 지침 50.4% 축소에 단순 비례시킬 수 없고, 상시 19.5% 절감 보장도 없다.

## 판단과 적용 경계

**축소 방향은 유지할 가치가 있다.** 이번 사전 기준에서 중대 기능/권한/완료 판정 실패 없이
두 과제 모두 시간·사용량이 낮았다. 그러나 품질 개선이나 모든 운영 조건의 비열등성은 미입증.
과거 근거 정정 차이도 있으므로, 후보를 그대로 제품 전체에 적용할 근거로는 부족하다.

이번 실험은 여기서 종료한다. 결과를 좋게 만들기 위한 추가 실행·규칙 보강은 하지 않는다.
사용자 판단 전 제품/설치는 유지. 제품화한다면 같은 원칙의 중복 표현을 줄이는 변경과,
읽기 우선순위·자료 출처·필수 검사·공동 편집 책임을 실제로 덜 명시하는 변경을 분리해야 한다.
후자는 이 시험에서 검증하지 않았다. 특히 외부 필수 검사를 연결한 경우와 조건부 자료를
찾아야 하는 경우는 시험하지 않았으며, 기존 검사 도구가 통과할 것이라고 추정하지 않는다.

한계: 두 작은 중립 프로젝트, 단일 작업 후 인계 기록까지만 확인. 새 담당자 인계 실행,
장기 누적, 실제 저장 프로젝트 자동 로딩, 시각/게임 품질, 사용자 수락은 범위 밖.
부모의 코드/문서 검토는 판을 알고 수행했다. 공통 요청에도 보존·기록 지시가 있어
연결문에서 빠진 지시의 영향을 가릴 수 있다. 두 판 모두 같은 호스트/저장소 지침을 받음.
