# 파일 이동 형식과 인계

## 현재 결과

화면의 **백업 저장**과 **백업 가져오기**로 기록을 파일로 옮긴다. 네트워크 전송은 없다. 내보내기는 저장소를 다시 읽어 저장된 전체 기록을 포함하고 검색 조건·미저장 초안은 포함하지 않는다. 다운로드 요청 뒤 파일이 실제 저장됐는지는 사용자가 확인한다.

UTF-8 JSON, 확장자 `.json`, 파일명 `teum-backup-<UTC 날짜와 시간>.json`:

```json
{
  "format": "teum-notes",
  "version": 1,
  "exportedAt": "2026-10-17T12:00:00.000Z",
  "notes": [
    {
      "id": "example-1",
      "body": "가상 현장 메모",
      "category": "idea",
      "createdAt": "2026-10-17T09:00:00.000Z",
      "updatedAt": "2026-10-17T09:00:00.000Z"
    }
  ]
}
```

`exportedAt`은 내보낸 시점의 안내 정보다. 분류는 `idea`, `todo`, `observation`, `other`의 문자열만 허용한다. 본문은 비어 있지 않은 최대 2,000 UTF-16 코드 단위, ID는 영문·숫자·밑줄·하이픈 1–128자, 기록 날짜는 UTC ISO 문자열이다. 한 파일 안의 ID는 중복될 수 없다. 최대 10,000개 기록, 파일 최대 25MB이며 브라우저 저장 용량은 별도다.

이전 `{ "version": 1, "notes": [...] }` 파일과 UTF-8 BOM도 읽는다. 다른 `format`이나 미지원 `version`은 거부한다. 저장소 형식은 기존 `teum.notes.v1` 키와 `{ version, notes }`를 유지한다.

## 기존 기록 보존 규칙

- 현재 기록을 삭제하거나 덮어쓰지 않고 추가한다. 새 ID는 그대로 보존한다.
- 같은 ID와 같은 내용·분류·생성일·수정일이면 건너뛴다. 내용이 다르면 새 ID의 사본을 만든다. 이미 같은 사본을 가져왔다면 재가져오기로 늘리지 않는다.
- 확인창에 추가·충돌 사본·중복 수를 표시한다. 전체 파일을 먼저 검증하고 확인 후 한 번 저장한다. 빈 파일 목록은 아무것도 바꾸지 않는다.
- 손상·잘못된 필드·용량 초과·파일 읽기 실패·취소는 기존 저장 원문과 초안을 유지한다. 정상 일부만 몰래 가져오지 않는다.
- 가져온 기록과 마지막 삭제 기록의 ID가 충돌해도 되돌리기는 삭제 원본을 사본으로 복원한다.
