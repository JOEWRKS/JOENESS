# JOENESS project connection

- Owners: AGENTS.md = work rules and source navigation; product.md = approved
  product meaning and scope; ROADMAP.md = whole-project delivery scope/order,
  item status/criteria/proof/gaps/next; TASK.md = per-work results and checks;
  ISSUES.md = unresolved cause, workaround, residual risk and closure conditions;
  DESIGN.md = visual scope/authority; Library/numeric-representation.md = topic
  research with sources. Historical notes and HANDOFF are source evidence, not
  competing current plans. notes/reviewer-plan.md is a separate optional experiment.
- Read by task: new/resumed work starts at the relevant ROADMAP item, then related
  TASK, ISSUES, actual target and linked proof. Defects start at ISSUES + target;
  visual work reads scope then DESIGN; research reads the relevant Library topic;
  direction changes consult product.md; completion/handoff traces all required
  roadmap items, proof, open issues and applicable approval. Read relevant
  sections, not all history; ordinary work does not invoke setup again.
- Resolve intent at the approved owner and facts at current target/proof. Code,
  newer notes and old handoffs do not grant approval. Preserve local,
  dependency-free scope and the existing product decision boundary below.
- Recording consent approved 2026-10-06: record factual results/checks/proof of
  authorized work in TASK; update only affected ROADMAP state/gaps/next; maintain
  relevant unresolved cause/workaround/risk/closure in ISSUES. Reusable research
  belongs in its Library topic with source, checked date, observation versus
  inference, scope and uncertainty. Detail has one owner; summaries link to it.
  Use existing topics before creating or splitting files. Preserve dated evidence.
- Recording consent does not authorize implementation, product scope/order/
  criterion changes or visual decisions. Such changes need applicable user
  direction. No-record requests disable record writes without cancelling
  separately authorized implementation. Questions or unchanged facts create no
  repeated record. Report write gaps without erasing completed work.
- Before work, check item order and entry conditions. Before stage/release
  completion, inspect every required outcome and actual proof; missing checks
  and holds remain open. Reuse applicable evidence; rerun only for a named change,
  failure or uncovered condition. A failed lookup does not prove no check exists.
  A workaround is not closure; task completion, technical verification and
  required user acceptance are separate. Scope removal needs an authorized
  reason and is not a pass. Independent authorized work may proceed while
  dependent work remains blocked. Update affected current/next before handoff.
- After substantive work or human handoff, start with six short Korean bullets:
  작업 = performed work; 업데이트 파일 = actually changed files by purpose;
  이슈 = encountered problem; 해결 = verified fix, not a passing check;
  남은 문제 = unresolved/unverified work; 다음 작업 = authorized next action.
  Use 없음 for empty fields. Add brief 상세 보고 only for necessary evidence,
  cause, scope or approval limits. Simple questions need no work report.
