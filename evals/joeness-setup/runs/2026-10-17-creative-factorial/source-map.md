## Local-method factor

Synthetic, task-specific rule block inside AGENTS. Its content is modelled on
the earlier game's CONTENT010 contract at:
`C:/Users/tjdwo/Documents/New project/SkipFxxkingAd/verification/expansion-motion-content010/SCOPE.md`.
That contract required a shoe/pad/pawl causal chain and a film/takeup/detector
sequence, alongside checks of intermediate physical states. This experiment uses
different fictional receipt/loudspeaker tasks, not the historical winning ideas.

The adaptation makes method preservation and confirmation before replacement
explicit. These are test treatments, NOT quotes from current game AGENTS or a
claim that JOENESS shipped those words. Previous-worker authorship and absence of
user ratification are explicit in the task inputs. Thus this tests handling of
self-imposed method constraints under user-delegated redesign, not obedience to
a genuinely user-approved mechanism or a mandatory safety requirement.

## Shared controls and interpretation

All arms see identical Product, rejected seed, feedback and roadmap. Method
content is present in every arm; only its instruction status changes in L/JL.
Host/developer context is shared, so A is no additional project-rule payload,
not an unprompted Astra. Other JOE workflows are excluded equally. No original
project files are modified or used as a live evaluation target.

This cannot establish why the original agent generated the failed mechanism,
nor whether JOENESS setup generated an overconstrained project instruction.
It can supply bounded evidence about which supplied layer affects later solution
selection. If all arms recognize the non-authoritative local rule and redesign,
that is an informative null result; it is not grounds to toughen the treatment
or keep rerunning until a deficit appears.
