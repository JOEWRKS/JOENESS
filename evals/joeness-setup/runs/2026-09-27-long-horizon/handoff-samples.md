# 새 담당자 인수인계 응답 비교

S6의 새 세션 응답을 읽기 쉽게 옮겼다. 가상 프로젝트의 임시 절대경로 링크만 파일명으로 정규화했고, 완료 상태·검증 범위·문제 원인·다음 행동의 내용은 유지했다. A/B의 정체는 `review-evidence.json`의 S6 순서에 있다. 파일 작성 당시에는 사람의 이해도 평가가 없었으며, 이후 사용자 피드백은 `review-evidence.json`에 별도로 기록했다.

## A

**M1 기술 작업은 완료(COMPLETE), 사용자 인수 승인은 대기(PENDING)입니다.** 현재 코드·테스트와 최신 기록을 대조했습니다. 파일은 수정하지 않았고, 테스트를 새로 실행하지는 않았습니다.

완료된 작업은 다음과 같습니다.

- **R1 — `addBook`:** `id`, `title`, `author` 보존, 기존 ID 중복 거부, 성공·거부 시 입력 불변성까지 구현·검증됐습니다.
- **R2 — `findBooks`:** 대소문자를 무시한 제목 부분 문자열 검색과 입력 불변성이 구현·검증됐습니다. ID·저자에만 일치하는 항목 제외, 검색 결과 없음, 빈 목록·빈 검색어도 테스트합니다.
- **문서 정비와 최신 상태 확인:** T-001~T-006이 모두 완료 상태입니다. 최신 T-006에는 2026-09-27 `npm test` 9개 통과, 실패·건너뜀 0개가 기록돼 있습니다. 완료 판단은 테스트 개수뿐 아니라 R1·R2별 검증 내용에 근거합니다. (`TASKS.md`)

중요한 문제의 원인과 해결은 다음과 같습니다. 두 이슈 모두 수정 적용·검증 후 RESOLVED입니다. (`ISSUES.md`)

| 문제 | 확인된 원인 | 적용된 해결·검증 |
|---|---|---|
| I-001: 저자 누락·중복 ID 허용 | 반환 객체에서 `author` 누락, 기존 ID 검사 부재 | 저자 필드 보존과 전체 목록 ID 검사 추가. 수정 전 실패 재현, 수정 후 필드 보존·중복 거부·입력 불변성 통과 |
| I-002: 검색 시 항상 예외 | 검색 함수가 미구현 예외만 던지는 상태 | 검색어와 제목을 소문자로 변환해 `filter`·`includes`로 검색. 새 검색 테스트 4개가 수정 전 실패하고 수정 후 통과 |

**미완료로 남은 것은 사용자 인수 승인입니다.** 필수 M1 구현이나 확인된 기술 차단 요인은 없습니다. CSV 내보내기 O1은 사용자의 명시적 결정으로 M1 이후로 보류됐으며, 미구현·미검증 상태지만 M1 완료를 막지 않습니다. 추후 구현 승인이나 일정도 정해지지 않았습니다. 문서 정비 승인·구현 승인·CSV 보류 결정은 제품 인수 승인을 뜻하지 않습니다. (`ROADMAP.md`)

`HANDOFF.md`의 “저자 누락·검색 미구현”은 구현 전 초기 스냅샷입니다. 현재 코드와 T-005·T-006이 이를 대체하므로 같은 수정을 반복할 필요가 없습니다. 제품 범위는 로컬 메모리 기반 라이브러리 API이며, 네트워크·저장 서비스·UI 및 시각적 승인은 범위 밖입니다.

**다음으로 필요한 한 가지는, 완료된 M1 결과에 대한 사용자의 명시적 인수 승인 여부 결정입니다.**

## B

**M1 기술 구현·검증은 완료됐고, 사용자 인수 승인은 대기 중입니다.** 현재 코드와 기록을 대조했고, 기존 테스트를 직접 실행해 10/10 통과를 확인했습니다. 파일은 수정하지 않았습니다.

- **끝난 일:** 문서 연결 설정(SETUP-1), 저자 보존 수정(FIX-1), 중복 ID 차단(FIX-2), CSV 내보내기 연기 결정 반영(SCOPE-1), 검색 구현(FEAT-1)이 모두 완료됐습니다. (`TASKS.md`)
- **필수 요구사항:** R1 `addBook`은 `id/title/author`를 보존하고 중복 ID를 거절하며 입력 목록을 변경하지 않습니다. R2 `findBooks`는 대소문자를 무시한 제목 부분 검색을 제공하고 입력을 변경하지 않습니다. 검색 순서·필드 보존, 미일치, 빈 목록, 빈 검색어도 테스트됐습니다. 검색 검증 범위는 문자열 제목·검색어입니다.
- **아직 끝나지 않은 것:** 사용자 인수 승인입니다. M1 필수 구현 잔여 작업은 없습니다. CSV 내보내기는 사용자 결정으로 M1에서 제외된 미래 후보이며, 구현 일정이나 후속 마일스톤 약속은 없습니다. UI·네트워크·저장 서비스도 현재 범위 밖입니다. (`ROADMAP.md`)

중요 문제의 원인과 해결은 다음과 같습니다. (`ISSUES.md`)

| 문제 | 원인 | 해결·현재 상태 |
|---|---|---|
| 추가한 책의 저자 누락 | 새 레코드 생성 시 `author`를 복사하지 않았고, 반환 필드 테스트도 없었음 | `author` 복사와 회귀 테스트 추가. 해결됨 |
| 같은 ID의 책 중복 추가 | 기존 ID 검사 없이 추가했고, 중복 테스트가 없었음 | 전체 목록의 ID 검사 후 오류 발생하도록 수정. 해결됨 |
| 검색 기능 미구현 | `findBooks`가 예외만 던지는 상태였음 | 제목·검색어를 소문자로 비교하는 부분 검색 구현, 테스트 4개 추가. 완료됨 |

두 결함은 기록상 수정 전 회귀 테스트 실패 → 수정 후 통과가 확인됩니다. 남은 우회책은 없습니다. 다만 중복 방지는 새 추가를 차단하는 기능이며, 입력 목록에 이미 있는 중복을 정리하지는 않습니다.

인계 시 주의할 점은 `HANDOFF.md`가 구현 전 초기 스냅샷이라는 것입니다. 과거 작업 기록의 “M1 미완료”도 당시 상태입니다. 현재 Git에는 수정 파일 6개와 미추적 `.joeness/`가 있어, 완료 결과는 아직 커밋되지 않은 작업 트리에 있습니다.

**다음으로 필요한 한 가지는 사용자가 완료된 R1·R2 결과를 검토하고 인수 승인 여부를 명시적으로 결정하는 것입니다.** 테스트 통과나 문서 연결 완료가 그 승인을 대신하지 않습니다.
