# 새 담당자 인수인계 읽기 비교

같은 실제 프로젝트의 동물 스킨 후보를 두 방식으로 기획한 뒤, 각각 새 담당자가 파일을 읽고 작성한 답변이다. A/B의 출처는 평가 전 공개하지 않는다. 경로만 시험 복사본으로 통일했다. 사실·숫자·문장 구조는 유지했다.

## A

작업: 현재 파일·Git 기준 동물 스킨 후보 인수인계.
업데이트 파일: `TASK.md`만 130줄 추가된 미스테이징 상태. 이번에는 수정 없음.
이슈: 후보 기획 완료와 제품·디자인 승인은 별개.
해결: 없음.
남은 문제: 채택·표현·해금 등의 결정과 실제 제작·구현·검증.
다음 작업: 사용자에게 채택 여부·대상 릴리스·후속 작업 허용 범위를 확인.

- **승인된 기준:** 기존 Default·Pixel·Cute·Slime 네 세트와 공유 게임·점수·랭킹이다. 해금은 각각 기본 제공·첫 Watermelon·한 판 3,000점·6,000점. 동물 후보에 대해 기록된 지시는 **다섯 번째 후보 기획과 인수인계까지**다. Cute의 얼굴·Slime 예외가 동물 표현까지 승인하지 않는다.
- **이번 제안:** 둥근 동물 몸체에 굵은 외곽선·절제된 명암·종이 질감을 적용하고, 기존 10티어에 대응시킨다. Slime 다음 컬렉션 페이지와 기존 선택·확인·재시작 흐름을 재사용한다. 제작 허용 후 소·중·대 대표 외형부터 검토한다.
- **미결정:** 채택·출시 시기, 동물 종류·순서·반복, 머리/전신, 얼굴·표정, 한영 이름, 해금 조건, 준비 중 노출·안내 문구, 난이도 별 수. **10티어가 서로 다른 동물 10종을 뜻하지 않으며, 9,000점 해금도 승인되지 않았다.**
- **미구현·미검증:** 현재 enum·카탈로그에는 기존 ID 0–3만 있고 동물 항목은 없다. 그림 원본·화면·물리 공정성·저장/랭킹 호환성·기기 동작은 확인되지 않았다. 과거 717개 테스트·AAB 기록은 이번 검증 결과가 아니다. 후보 기록은 Ticket 13의 출시 기준을 바꾸지 않는다.

## B

동그란 동물 캐릭터 스킨은 **다섯 번째 후보로 문서화된 상태**이며, 채택·디자인·제작·구현·출시는 승인되지 않았습니다.

- **기존 승인 사실:** 네 세트(Default·Pixel·Cute·Slime), 공통 10티어와 게임 규칙·단일 랭킹, 세트별 그림과 충돌 형태, 선택 확인 후 새 판 시작 구조입니다. 기존 얼굴 표현 승인이 동물 후보에 자동 적용되지는 않습니다.
- **이번 제안:** 기존 세트 다음에 동물 후보를 추가하고, 10티어에 둥근 동물 외형을 대응하며 Collection 흐름을 재사용하는 안입니다. 동물 10종을 뜻하지 않으며, 둥글다는 이유로 원형 콜라이더나 쉬운 난이도를 확정하지 않았습니다.
- **미결정:** 동물 구성·티어 배정·얼굴과 표정·미술 방향, 한영 이름·과일 관련 문구, 해금 조건, 노출 순서·출시 예정 페이지, 난이도·랭킹 아이콘, 제작 범위와 릴리스 시점입니다. `9,000/12,000/15,000점`은 기존 확장 예시일 뿐 후보 조건이 아닙니다.
- **미검증:** 현재 enum과 카탈로그에는 네 세트만 있습니다. 이 사본에는 실제 그림·Scene·전체 런타임·검증 결과가 없어 설치본 동작과 품질을 확인할 수 없습니다. 과거 717개 테스트 통과 기록은 동물 후보의 검증 근거가 아닙니다.
- **수정된 파일:** Git상 `TASK.md`만 미커밋 변경 상태이며, 안내 링크와 후보·인수인계 기록 **122줄 추가**입니다. 이번 읽기 작업에서는 파일을 수정하지 않았습니다.
- **다음 행동:** 후보 채택과 후속 작업 범위를 먼저 결정한 뒤 미정을 구체화합니다. 실제 UI/UX 착수 전 지정 스킬 `joewrks-design-frontend`의 가용성을 확인하고, 구현 시 전체 프로젝트의 저장 호환성·Collection·현지화·랭킹 사용처를 조사해야 합니다. 기존 Ticket 13과 Play 일정에는 아직 편입되지 않았습니다.
