# JOENESS 1.0.0

## 1. 이게 뭐냐

**작업이 어디까지 됐고 무엇이 남았는지 관리한다.**

세줄요약:

1. 목표·작업 순서·완료 조건을 단계별 로드맵으로 정리합니다.
2. 계획·결과·문제·디자인을 각 문서에 나누고, 필요한 순서로 찾아봅니다.
3. 작업 뒤에는 한 일과 남은 일을 여섯 항목으로 먼저 보고합니다.

소스 버전은 **1.0.0**입니다. [검증·게시 기록](evals/joeness-setup/runs/2026-10-13-v100-candidate/review-evidence.md). 개인 설치는 자동으로 갱신되지 않습니다.

## 2. 언제 쓰냐

- 새 프로젝트: 무엇부터 할지, 어디까지 해야 끝인지 정할 때.
- 진행 중인 프로젝트: 흩어진 계획과 기록을 정리할 때.
- 작업 재개·인수인계: 끝난 일·남은 검증·다음 행동을 찾을 때.

## 3. 바로 시작하기

Windows PowerShell에서 저장소를 받습니다. 이미 받았다면 해당 폴더에서 시작하세요.

```powershell
git clone https://github.com/JOEWRKS/JOENESS.git
cd JOENESS
powershell.exe -NoProfile -File .\JOENESS.ps1 -Check
```

`ready`일 때만 설치합니다. `current`는 같은 설치본이 있다는 뜻입니다. `blocked`이면 덮어쓰지 말고 [업데이트·복구 안내](docs/installation.md)를 따르세요.

```powershell
powershell.exe -NoProfile -File .\JOENESS.ps1 -Apply
powershell.exe -NoProfile -File .\JOENESS.ps1 -Check
```

설치 후 Codex에서 **사용할 Git 프로젝트**를 열고 요청합니다.

- 새 프로젝트: `이 프로젝트에 JOENESS 설치해줘. 목표는 [목표]. 만들 문서와 기록 범위를 먼저 보여줘.`
- 기존 프로젝트: `이 프로젝트에 JOENESS 설치해줘. 기존 계획·결과·승인 근거를 보존하고 정리안을 먼저 보여줘.`
- 변경안 승인: `이대로 적용해줘.`
- 평소 작업: `로드맵에서 다음으로 가능한 작업을 이어서 진행해.`

개인 도구 설치와 프로젝트 문서 정리는 별개입니다. **승인 후에만** 프로젝트 파일을 만듭니다. 매 작업마다 다시 설치할 필요는 없습니다.

## 4. 무엇을 받게 되냐

프로젝트에는 다섯 문서를 기준으로 작업을 정리합니다. 기존 내용은 승인한 범위에서 보존·재배치합니다.

| 파일 | 역할 |
|---|---|
| `AGENTS.md` | 작업 규칙과 문서 위치 |
| `ROADMAP.md` | 목표·단계별 체크리스트·현재 상태·다음 작업 |
| `TASK.md` | 한 일과 검증 결과 |
| `ISSUES.md` | 미해결 문제·우회책·남은 위험 |
| `DESIGN.md` | 디자인 기준과 승인 범위 |

조사·참고 자료는 필요할 때 `Library/`에 주제별로 보관합니다. 제품 기준 원본은 별도로 유지합니다. [문서별 책임·읽는 순서](skills/joeness-setup/references/usage.md#문서-구조와-책임).

작업 보고 예시:

- 작업: 예약 취소 오류 수정.
- 업데이트 파일: 예약 기능, 검사, 작업 기록.
- 이슈: 취소하면 예약 내역도 삭제됨.
- 해결: 취소 상태만 바꾸도록 수정·확인.
- 남은 문제: 실제 행사장 기기에서 확인 필요.
- 다음 작업: 해당 기기에서 예약·취소 시험.

`이슈`는 발생한 문제, `해결`은 확인한 조치, `남은 문제`는 미해결·미검증입니다. 필요한 근거만 뒤에 설명합니다. 단순 질문에는 이 형식을 강제하지 않습니다.

## 5. 다른 JOE 도구와 함께 쓰기

| 도구 | 역할 |
|---|---|
| [JOENESS](https://github.com/JOEWRKS/JOENESS) | 작업이 어디까지 됐고 무엇이 남았는지 관리한다. |
| [JOEFLOW](https://github.com/JOEWRKS/JOEFLOW) | 무엇을 만들지 확실하게 정한다. |
| [JOEDESIGN](https://github.com/JOEWRKS/JOEDESIGN) | 어떻게 보이고 사용될지 만들고 확인한다. |

**JOENESS로 작업 정리 → JOEFLOW로 만들 것 확정 → JOEDESIGN으로 화면 제작·검수 → 구현 담당이 개발 → 결과 검증 → JOENESS에 완료·잔여 기록.**

예를 들어 예약 기능이라면, JOEFLOW의 예약·취소 규칙과 완료 기준을 JOEDESIGN·구현 담당에게 넘깁니다. 디자인 담당은 화면 기준과 검수 결과를, 구현 담당은 개발·시험 결과를 넘깁니다. JOENESS는 그 원본을 연결해 로드맵에 끝난 일과 남은 검증을 기록합니다.

JOENESS는 전 과정에서 사용하며, **각 도구는 단독 사용도 가능**합니다. 다른 도구를 자동 실행하거나 사용자 대신 승인하지 않습니다. [필요한 항목에 검증 결과 연결하기](skills/joeness-setup/references/review-gate.md).

## 6. 지원 범위·주의사항

- 지원: Codex, Windows PowerShell 5.1/7, Git 프로젝트의 UTF-8 문서. 선택형 검증 도구는 Node.js 18 이상 필요.
- 프로젝트 변경은 변경안 승인 뒤 적용. 목표가 없으면 결정 대기로 남기며, 완료·디자인 승인을 지어내지 않습니다.
- 설치 성공·문서 정리·지침 전달·작업 검증은 별개입니다. 필수 검증과 사용자 수락이 남으면 전체 완료가 아닙니다.
- 상시 감시·자동 업데이트·강제 잠금 기능은 없습니다. 기존 프로젝트와 열린 채팅은 자동 갱신되지 않습니다.
- 검사 재사용은 근거가 확인된 제한 범위만 지원합니다. CSS·동적 변경을 모두 판단하지 않으며, 읽기 전용 검사가 말로만 하는 완료 선언까지 차단하지는 않습니다.
- 토큰 절감·일반적인 성능 우위·모든 환경의 안정성을 보장하지 않습니다. 비밀번호·인증키·불필요한 개인정보는 기록하지 않습니다.
